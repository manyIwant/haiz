# 春天没有收件人 · v2

**A World That Poetry Remembers**

一部约三分钟的短片（1920×1080，30 fps）。它从一次真实的 Claude Code 编程实验开始，经过 N-gram 的一个“路口”，进入一个由两首诗记住的世界。

- 成片：`spring-no-recipient-v2.mp4`（发行版，HEVC，<100 MB）
- 母版：`build/master.mp4`（H.264 高码率；不进仓库，可用 `render/render_all.sh` 重新生成）
- 旧版（v1，7:26）完整保留在 `../spring-no-recipient/`，可直接对比。

## 一、导演构想

### 一个真实的路口

在录屏里那次真实运行的 80 行输出中，有两行来自同一个路口：

| 行 | 程序打印的句子 | 在“有一”处抽到 | 来源 |
| --- | --- | --- | --- |
| 第 37 行 | **河上有一条河很长** | 条（1/3） | 终端屏幕上实时出现过（约 0.15 秒） |
| 第 23 行 | **我家门前有一个名字** | 个（1/3） | 同一次运行写入 `output_things.txt`，没有显示在屏幕上 |

字级 3-gram 每写一个字，只看前两个字。语料里“有一”后面只出现过三个字，各一次：
**条**（我家门前有一条河）、**个**（我家墙上有一个钟）、**座**（河上有一座桥）。

于是程序在同一个路口写出了两个世界：一条躺在河上的河；以及一扇门前，原本是一条河的地方，变成了“一个名字”。

整部影片就从这里长出来：
- **诗的世界，是那条被句子遗漏的河。** 第 23 行里，河的位置被“名字”占走了，所以后来“河流还不知道自己的名字”不需要任何解释。
- 路口没被选中的另外两个分支，钟和桥，都成了这个世界的一部分。
- 诗里的车站、钥匙、窗户、钟表，也都来自同一份语料。

### 世界

一个连续的、不符合现实地理的地方，三处主要空间：

1. **黄昏的教室**：一楼。三扇朝西的旧钢窗，窗台下面直接就是河，没有操场。
2. **河**：认得出窗户，它的倒影会记住已经不在的东西。
3. **空车站**：站台的轨道是河，站名牌上没有名字。

另外还有上游一座低矮的平桥，也就是路口第三个分支“座”。河床下面沉着一条跑道：这条河在“现实”里，本来是学校的操场。

### 关键镜头

- **终端 → 河**：程序输出里只剩下一个“河”字。下一帧，同一个“河”字成了水面上的倒影；一滴水落下，倒影散开，镜头从水面抬起，看见那栋楼。
- **升起来的世界**：一个连续的升降镜头。镜头沿着爬满爬山虎的墙一路升到屋顶以上，第一次看见这条河通向哪里：它笔直地伸向地平线，经过那座桥，两岸是柳树和芦苇，黄昏的雾里有逆光的光束。
- **穿过窗户**：镜头从河面贴水滑行，穿过那扇半开的窗进入教室。教室里有一封信，有一扇窗在阳光里下雨。之后镜头又从同一扇窗退回河面，回头看时，河的倒影里，那些窗户是亮着的（现实中它们并没有亮）。
- **影子认出了另一个早晨**：太阳从西边倒着回来，越过头顶走到东边，窗格的影子从黄昏扫到早晨。第二首诗由此开始。
- **月亮走过操场**：早晨的河变得清澈，看得见河底那条跑道，白天的月亮从跑道线上掠过。
- **河流替山记住了全部花期**：岸上的柳树是绿的，河里倒映的柳树、远树和远山却开满了粉白的花（倒影单独渲染一遍，把叶子的颜色换成花色，保留叶片原有的明暗）。
- **河流还不知道自己的名字**：水流停住，水面变成镜子，然后连倒影也褪去，河变成一张空白的、没有任何联系的平面。声音跟着画面一起退去：最后一个高音和混响在约两秒内衰减下去，从约 2:15.5 起低于 -50 dBFS（几乎听不见），2:18.6–2:19.4 是数字静音，2:19.4 水声先回来，音乐更晚。实际“听不见”的时间约四秒。
- **结尾**：回到最初那扇窗。凌晨，河上起雾，窗台上放着那把钥匙（第一首诗里“请把钥匙放在靠窗的位置”）。最后一句诗结束后，只剩下水声和教室里的钟，然后安静下来。

## 二、真实性说明

| 内容 | 性质 |
| --- | --- |
| 开头的终端画面 | **真实终端记录的回放**：2026-11-21 04:38 的 Claude Code v2.1.330 会话，`script` 记录了每一个字节和时间戳（`../spring-no-recipient/recording/`），xterm.js 逐字节回放，**不是原生屏幕录像**，片中左上角已注明。所有终端片段都按 1× 原速播放，不倍速；省略的部分是跳剪，并标出跳过的时长。光标闪烁按终端的通常行为计算（亮 600 ms、灭 600 ms，每次写入后重新开始）。会话中没有记录过鼠标，所以画面里也没有鼠标指针。终端的推近是剪辑时的取景，相当于对录屏做缩放。 |
| 定格 | 第 37 行在真实屏幕上只出现了约 0.15 秒（rec 192.16–192.31 s）。片中在这一刻定格，并标出“定格”。 |
| 第 37、23 行与路口概率 | **程序原样输出与真实计数**。`analysis/fork.py` 会重新运行 `modern.py 1 80 corpus_things.txt`，断言结果与 `output_things.txt` 逐字相同，并核对“有一”后面 条:1 个:1 座:1。路口图里的三句语料原句都是真实语料。 |
| 两首诗 | **此前人机共创的诗稿**，参考 N-gram 的拼接思路，经人工挑选、排列与修改。**不是这次程序的输出**。片中每首诗的标题下都有一行小字说明，片尾再说明一次。 |
| 教室、河、车站 | **艺术化的三维影像**：Blender 建模，Cycles 烘焙光照，Three.js 拍摄。 |
| 声音 | 原创。没有使用任何现有音乐或录音（见第四节）。 |

## 三、制作方式

| 层 | 技术 |
| --- | --- |
| 纹理 | `world/textures.py`：用周期性谱合成噪声，逐张合成可无缝平铺的 PBR 贴图，包括石灰墙、绿色油漆墙裙、水磨石、课桌木纹、黑板（上面留着擦不干净的旧字）、混凝土、外墙、花岗岩、瓦楞板、窗帘布、水面法线，以及没有名字的站名牌。没有使用任何照片。 |
| 场景 | `world/build_world.py`（bpy 5.3）：三层教学楼（每层五间，钢窗、走廊、楼梯间）、主教室（28 张双人桌、56 把椅子、讲台、黑板、挂钟、吊扇、日光灯、窗帘、扫帚和水桶）、河岸、平桥、车站（站台、雨棚、灯、长椅、排队栏杆、候车室）、河床下的跑道。几何体按光照贴图分组。 |
| 光照 | `world/bake.py`：用 Cycles 把漫反射直接光与间接光烘焙进光照贴图（不含反照率），分黄昏、早晨、凌晨、夜晚几个状态，外加“无太阳”版本供影子扫过时使用，再用 OIDN 降噪。天空使用 Blender 的多重散射天空，`world/sky.py` 把它渲染成全景图，所以 Three.js 的背景和反射与烘焙时的天空一致。 |
| 拍摄 | `film/`（Three.js r170，离线逐帧确定性渲染，所有贴图与光照贴图预加载完成后才开始出帧）：烘焙材质（反照率 × 光照贴图，两个状态之间可以交叉过渡）、自定义河水（平面反射、折射与吸收、流动的法线；倒影可以替换成终端画面、亮着的窗户、开花的山，或者什么也不映）、阳光穿过教室的体积光和只在光里出现的灰尘、风中摆动的柳树和芦苇、楼墙上程序生成的爬山虎、伸到地平线的河与两岸、屏幕空间的太阳光束、车站灯下的雾光锥、远山、远处的树、高空云、白天的月亮、HDR 管线、泛光、AgX 色调映射与调色、胶片颗粒。 |
| 终端与路口 | `film/term.html` / `film/term.js`：xterm.js 回放真实字节流，路口图用 DOM 排版；数据来自 `analysis/fork.py` 生成的 `film/data/fork.js`。 |
| 声音 | `music/score.py`：钢琴用 FluidR3 GM（MIT）经 FluidSynth 渲染，其余全部用 numpy 合成，包括垫音、钟声、水、风、芦苇、鸟、钟表滴答、键盘声。键盘声落在 `keys.txt` 记录的真实按键时刻。 |
| 合成 | `render/render_all.sh`：多个 Chromium（SwiftShader）进程分段渲染，经 ffmpeg 拼接；终端与河之间做 0.8 秒溶接；响度标准化到 -16 LUFS。 |

## 五、重新生成

依赖：
- Python 3：numpy、scipy、Pillow、soundfile、pretty_midi
- bpy 5.3（`pip install bpy==5.3.0`，需要 Python 3.13）
- Node 22 + Playwright（自带 Chromium）
- ffmpeg、fluidsynth、`fluid-soundfont-gm`
- 字体：`fonts-noto-cjk`
- 无 GPU 时，烘焙用到 Mesa（libegl1 等）不是必须的；渲染使用 SwiftShader

```bash
python3 world/textures.py                                      # 贴图
/home/user/bpyenv/bin/python world/build_world.py              # 场景 -> assets/world.blend
/home/user/bpyenv/bin/python world/export.py                   # -> assets/world.glb
/home/user/bpyenv/bin/python world/sky.py dusk,morning,dawn,night
bash world/bake_all.sh                                         # 光照贴图（4 核 CPU 约 3 小时）
python3 analysis/fork.py                                       # 核对路口数据 -> film/data/fork.js
(cd .. && python3 -m http.server 8766) &                       # 两个页面都通过本地 HTTP 打开
bash render/render_all.sh 2                                    # 渲染 + 配乐 + 合成
```

预览单帧：

```bash
node render/film_preview.cjs out/ 58.5 120
node render/term_preview.cjs out/ 20 30
```

### 常见修改

- **镜头**：`film/film.js` 的 `SHOTS`。机位用 Blender 坐标（x 东、y 北、z 上），`K(时间, 位置, 注视点, 视角)`；标记 `cont: true` 的镜头与上一个镜头之间没有剪辑，共用一条样条曲线。
- **诗句的时间与位置**：`film/film.js` 的 `TEXT`。
- **调色与雾**：`GRADE`、`FOG`。
- **终端剪辑**：`film/term.js` 的 `SEGS`，每段写明影片时间与录屏时间。
- **配乐**：`music/score.py`。时间表与上面两个文件对应。

## 六、局限

- 渲染在 CPU 上完成：烘焙用 Cycles，拍摄用 SwiftShader。光照贴图分辨率和反射分辨率都受时间限制；远景的树是程序生成的简化体，近看能看出来。
- 终端是字节流回放，不是原生屏幕录像。原会话是在容器里用 `script` 录制的，当时没有屏幕可录。
- 我无法在这个环境里试听，配乐和声音设计只经过结构检查（电平曲线、频谱图、静音段的位置），**需要人工试听确认**。
- 参考曲目《千年之后》（氛围版）只作为情绪参考，没有引用它的旋律、和声或音频。
