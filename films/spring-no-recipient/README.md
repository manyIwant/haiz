# 春天没有收件人

一部关于 N-gram、接缝与阅读的短片（约 7 分 26 秒，1920×1080，30 fps）。

起点是一句真实输入 Claude Code 的话：`用 ngram 写两首诗`。
影片记录了那次会话里程序如何从语料中“数一数、再抽一个”，展示一行行看似有情感的句子是怎样在两个字的接缝处拼出来的，
最后把时间留给两首诗：《失物招领》《春天没有收件人》。

成片：`spring-no-recipient.mp4`（工程根目录；`render/mux.sh` 会在 `build/` 里重新生成）。

---

## 导演构想：接缝

字级 3-gram 模型生成每个字时，只看前两个字：先在语料里找出这两个字之后出现过的所有字，再按出现次数随机抽一个。
因此，生成的每一行都能拆回语料里的几句原话：前一句读到某两个字，后一句也恰好有这两个字，程序就从这里换到了后一句。

影片的核心画面就是这些**接缝**：

- 「外面有点饿了」=「外面**有点**冷，多穿一点」+「回到家我**有点**饿了」
- 「外面的雨还没有给我回信」=「外面的雨还**没有**停」+「他一直**没有**给我回信」

在第三份语料里，“没有”后面出现过六个字：停、写、去、寄、看、给，每个的概率都是六分之一。
六句原话都在说某种缺席。程序并不知道这一点，它只是在这里抽到了“给”。

影片前半段讲清楚机制，后半段只做一件事：慢慢读诗。

### 视觉语言

- **纸与光**：象牙色纸面带纤维质感，一束很慢的窗光在纸上移动，边角压暗。用纸的颜色，不用屏幕的黑。
- **真实终端是一件物体**：录屏保持原样的深色。远景时它像一块微微倾斜、带柔和投影的屏幕放在光里，入场时有景深虚化；推近阅读时转正。
- **手绘线**：接缝用陶土橙和石板蓝的细铅笔线连接，共享的两个字被一圈松散的笔迹圈住。
- **人的手**：80 行原始输出是一张打印纸，挑中的行用荧光笔一笔一笔划过。唯一的修改用校对符号 ‸ 插入。
- **诗**：墨色宋体，大量留白，镜头缓慢呼吸。“河流还不知道自己的名字”这一句，音乐静止，光也暗下来一点。
- 背景里漂浮着几乎看不见的、失焦的语料字。

## 真实性说明（片中以角标区分）

| 角标 | 含义 |
| --- | --- |
| 🔴 **真实录屏** | 2026-11-21 04:38 在容器中运行的 Claude Code v2.1.330（Opus 5.5）。`script` 记录了终端的每一个字节和时间戳（`recording/`），片中用 xterm.js 逐字节回放，没有重绘任何界面。等待部分加速（×2 / ×4）或略过空闲，画面中都有标注。 |
| ⚪ **原始输出** | 程序原样打印的句子，未改一个字。第三轮的 80 行来自 `session-files/output_things.txt`。 |
| 🟠 **可视化** | 依据录屏中 Claude Code 写下的语料重新统计的真实计数（`analysis/trace.py` → `data/trace.json`）。概率条的宽度就是次数，没有为了效果改动数据。接缝拆分用的是“最少原句覆盖”，用来解释*为什么这一行能被生成*；程序本身只按次数抽字，并不会选择句子。 |
| 🟠 **筛选 / 人工修改** | 片中从 80 行里亮起的 7 行，是本片制作时挑选的。小诗里唯一的修改“声里”两个字用橙色标出。 |
| ⚪ **定稿** | 两首诗来自此前的 N-gram 创作实验，经过人工挑选、排列和少量文字调整。**它们不是本次录屏中程序的输出**，片中明确写出了这一点。 |

需要如实交代的细节：

- 三份语料（约 60 首唐诗、94 句日常话、100 句关于天气、车站、信、河、钥匙、名字、钟表的话）都是录屏中的 Claude Code 自己写的。唐诗是它凭记忆录入的，可能有个别字记错。片中直接说明：语料本身就藏着一个等信的人，这是意义的来源之一。
- 第一轮的唐诗程序带 25% 随机回退和句末约束，这是 Claude Code 自己加的，片中只把它作为“第一次尝试”展示。后面三轮是纯 3-gram（只看前两个字，不回退）。
- 第二、三、四轮的提示是拍摄时作为实验者输入的（换语料、换主题、比较窗口大小），都在录屏中完整可见。
- Claude Code 重绘界面时会清除终端的滚动缓冲，所以第三轮的第 34 行从来没有出现在屏幕上。影片没有伪造“往回翻”，而是高亮 Claude 自己写的那句“完整输出也存在了 output_things.txt 里”，再展示这个文件。
- 运行可复现：`python3 session-files/modern.py 1 80 session-files/corpus_things.txt` 的输出与录屏中逐字相同（`trace.py` 会先断言这一点）。

## 工程文件

```
recording/        真实会话的原始记录（script 字节流 + 时间戳 + 按键时间）
session-files/    录屏中 Claude Code 写下的全部代码、语料与输出（原样）
analysis/
  cast.py         录屏 → data/cast.json、data/recording.js
  trace.py        重新统计语料，解释片中出现的生成句 → data/trace.json、data/trace.js
film/
  cues.js         全片时间表（画面与音乐共用）
  film.js         确定性渲染：renderAt(t) 只依赖时间 t
  film.css, index.html, vendor/（xterm.js 5.5，MIT）
music/compose.py  原创配乐与音效（FluidSynth + FluidR3 GM，MIT）
render/
  preview.cjs     渲染指定时间点的静帧
  export_sfx.cjs  导出画面里的声音事件 → data/sfx.json
  render.cjs      多进程逐帧渲染 → build/video/
  mux.sh          拼接、响度标准化（-18 LUFS）、合成成片
```

### 重新生成

依赖：Python 3（numpy、scipy、soundfile、pretty_midi）、Node 22、Playwright 和 Chromium、ffmpeg、fluidsynth、sox、`fluid-soundfont-gm`，以及字体 Noto Serif/Sans CJK SC 和 JetBrains Mono。

```bash
python3 analysis/cast.py
python3 analysis/trace.py
node render/export_sfx.cjs
python3 music/compose.py
node render/render.cjs 3
bash render/mux.sh            # 高码率母版 → build/春天没有收件人.mp4
bash render/encode_dist.sh    # 发行版（HEVC，<100 MB）→ spring-no-recipient.mp4
```

只修改了某一段画面时，可以只重渲染那一段：`OUTDIR=build/patch node render/render.cjs 3 起始秒 结束秒`，再用 ffmpeg 的 trim 和 concat 按帧号拼回去。

预览单帧：在浏览器中打开 `film/index.html?t=200`；实时播放（无声）：打开 `film/index.html?play=240`。

### 常见修改

- **字幕和角标**：`film/film.js` 里的 `CAPS`、`TAGS`。
- **节奏**：`film/cues.js`。终端段落、各幕起止和诗句出现时间都在这里，音乐也读取这份时间表；改完后要重跑 `compose.py`。
- **挑选哪几行**：`film/film.js` 里的 `PICKED80`（第三轮输出中的行号）。
- **诗的文本**：`POEM1`、`POEM2`。
- **配乐**：`music/compose.py`。和声、旋律、各段配器都写成音符；`STEMS` 控制混音比例。
