# haiz-user-research

## 何时使用
让真正学生用任务证明是否更好；不能用模型自己的审美评价代替用户证据。

## 实施流程
1. 选择 5–7 个典型任务：查下一节课、记一个想法、把通知确认成任务、修改截止日、恢复已删除任务、开始专注、找备份。
2. 用虚构内容建立可操作测试账号与场景，提前规定成功标准：是否发现入口、几次操作、能否理解状态。
3. 观察误操作与迟疑点，不诱导用户；尊重学校隐私，不收集未经允许的真实学生资料。
4. 对比旧版/新版时间和成功率；如没有受试者，明确区分“专家评审”和“实测”。
5. 汇总反复出现的问题，优先改流程和信息层级，再微调视觉。
6. 每轮只保留真正改善操作的方案，避免单纯按主观“漂亮”决策。

## 验收条件
- 设计决定同时有用户任务与实现证据。
- 复杂功能能被初次使用者找到。
- 测试材料不暴露私人学生记录。
