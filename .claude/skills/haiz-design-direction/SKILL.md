# haiz-design-direction

## 何时使用
决定视觉语言：允许大胆，但不得把“高端”理解成光晕/玻璃/大圆角堆砌。

## 实施流程
1. 先写 3 个**真正不同**的方向，仅用于内部比较：如「有编辑气质的现代工具」「冷静精密的个人操作系统」「具有真实校园影像的温暖信息空间」。每个都需例证和局限。
2. 对同一组真实信息（下一节课、4 项待办、2 条待确认收件、无任务空状态）做同等分辨率对比，不允许假 KPI/空泛口号替代真实内容。
3. 用可运行的 Flutter UI 而不仅是长篇设计宣言进行比较；至少 1 个完整主页与其任务详情/收件状态。
4. 设计“视觉权重预算”：主要文字、辅助文字、交互、高价值信息、图像、材质依次有明确层级。
5. 选择一个方向并编写 `DESIGN.md`：颜色及其用途、中文字体和数字处理、比例、留白、容器规则、动效语言、平台差异、反模式。
6. 先实现清晰安静的基线，再加只有解释得清用途的复杂视觉。

## 验收条件
- 同一真实场景下比旧版更容易扫描、定位操作和区分状态。
- 主屏与详情有共同 DNA，但不机械重复同一种卡片。
- 能用具体设计决策解释“高级”，不依赖形容词。
