# haiz-information-architecture

## 何时使用
重新思考首页和信息流，允许重新设计五栏底部导航，不允许把全部工具挤进一个 Dashboard。

## 实施流程
1. 建立学生任务地图：“收到 → 确认 → 计划 → 执行 → 回顾”，和“今日课程快速查看”“临时随手记”两条快路径。
2. 统计主要交互路径触达数：新增任务、查看下一课、检查通知来源、修改截止日、撤销完成、进入设置。
3. 提出 2–3 个导航架构，使用可操作原型对比到达步骤/理解成本，不因新奇牺牲速度。
4. 明确命名、全局搜索、空状态、账号入口、通知入口、设置入口、深链、返回手势和已选择状态。
5. “校园”可作为真实内容入口，不要让它变成仅收集若干网页链接的混合菜单；未授权服务有独立受控说明。
6. 对新手/老用户/访客/已登录/断网/共用设备分别模拟任务路径。

## 验收条件
- 高频任务 1–2 次明确操作能开始。
- 用户能预测返回位置、草稿是否保留、消息下一步在哪里。
- 相同实体不会因为多个功能页面产生多个相互冲突的副本。
