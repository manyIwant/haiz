# haiz-reference-app-research

## 何时使用
参考成熟 App 的信息组织与行为机制，而不是把 Things 3、Linear、Craft 做成拼贴皮肤。

## 实施流程
1. 优先研究 Things 3（任务分组与编辑）、Linear（导航/密度）、Craft（内容层级）、Bear（编辑）、Notion Calendar/Fantastical（日程）、Raycast（命令效率）及 Apple HIG；只从可核实截图、文档、公开视频或合法试用中归纳。
2. 逐个记录：核心场景、屏幕截图来源/版本、密度、导航方式、空状态、输入反馈、撤销/错误状态、动效与性能代价。
3. 建立“观察到什么 → 为什么可能有效 → HAIZ 适用/不适用 → 需实际测试什么”的证据表。
4. 在多个产品出现矛盾时，以 HAIZ 的高中生日常使用场景决策；不用品牌名代替设计理由。
5. 不复制带版权的整屏设计、品牌图标、照片与文案。为 HAIZ 写原创组件和状态逻辑。

## 验收条件
- 至少 3 个成熟产品的具体界面行为得到分析。
- 至少 5 个可验证、与 HAIZ 使用场景相关的设计决定。
- 对重要引用提供可访问链接或截图文件；不编造参考结论。
