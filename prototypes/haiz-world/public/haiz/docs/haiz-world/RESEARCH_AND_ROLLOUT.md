# 访谈与试点准备（未执行）

没有真实教师访谈和学生试用结果；以下均为待验证问题与假设。

## 三名自愿教师访谈题纲

1. 回顾一周：哪三项重复输入、查找资料或活动协调最耗时？请展示一次去除个人信息的实际操作。
2. 下节课开始前，需要从哪些地方找资料？经常缺失什么？是否愿意手动录入少量课程？
3. 一场社团活动从提案到结束，谁负责哪些确认？哪些信息不应进入公开网页？
4. 如果只能保留一个模块，你会保留哪个？为什么？
5. 便笺、提醒与工作结束界面会减轻负担，还是造成额外维护？
6. 演示完成后，愿不愿意自愿再使用一周？不愿意的阻碍是什么？

## 3–5 次真人任务试用记录模板

参与者使用匿名编号；仅经本人同意记录屏幕与耗时。不采集班级、姓名、手机号。记录原始耗时与结果，不用美观推断留存。

| 任务 | 目标 | 待记录 |
| --- | --- | --- |
| 教师打开下节材料 | ≤3 步 / 60 秒 | 实际步数、耗时、失败原因 |
| 教师建活动草稿 | 30 秒内 | 是否发现仅需标题，是否成功保存 |
| 学生发现兴趣社团 | ≤3 步 | 是否理解虚构提案与活动状态 |
| 作者选择与撤回公开 | 准确理解范围 | 是否把本机演示误认成实际发布 |

## 风险与试点条件

| 风险 | 当前边界 | 试点前工作 |
| --- | --- | --- |
| 自选角色冒充教师 | 无真实身份或业务 | 学校认可的身份验证与服务端授权 |
| 未授权作品公开 | 本机状态机，逐件选择 | 作者、版本、双重审核与撤回传播 |
| 私有内容随静态站分发 | 无真实业务资料 | 受保护 API 与媒体存储 |
| 低端设备耗电 | 按需渲染、低功耗、暂停 | Intel Mac / Android 真机三分钟测量 |
| 版权与资料真实性 | 原许可保留、待核标记 | 权利人确认与来源逐条核验 |
| 教师多维护一套系统 | 手动示例，未宣称提效 | 先做三名教师访谈，再决定接口 |

真实试点仅在学校授权、用户同意、范围与服务地域明确后进行。生产后端、真实数据接入与试点均未在本次实现。
