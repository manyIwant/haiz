## A · 校园生活假设与验证

| 问题 | 场景假设（不是调查结果） | 阻力 | 验证方式 |
| --- | --- | --- | --- |
| 每天看几次课表？ | 可能集中在早到、课间和准备材料时；次数未知 | 后排看不清、老师投屏占用 | 授权观察 3 个班 5 天，记录查看时机，不追踪个人 |
| 调课如何传递？ | 可能通过口头、黑板或班级群多次转述 | 版本冲突、接收者不在场 | 访谈班主任、课代表，追溯 5 次真实调课链路 |
| 为什么漏通知？ | 通知出现时与学生能行动的时间脱节 | 屏幕关闭、字太小、重复轮播导致忽略 | 比较行动时段、理解正确率和漏带次数 |
| 教师何时重复说？ | 课前准备、截止时间、活动地点被反复询问 | 每个渠道都要再录入、缺少撤回 | 计数重复录入与重复说明分钟数，不以消息量评价 |
| 学习难在哪里？ | 不同任务可能难在启动、理解或中断后找回上下文 | 回家疲劳；输入记录本身也费力 | 让学生对一段真实中断前后任务做回顾，不预设答案 |
| 第十天为何不再打开？ | 新鲜感消退后，计时收益抵不过操作成本 | 打卡负担、空泛任务、装饰画面开销 | 自愿两周试用；以回到第一步所需时间和额外录入负担评价 |

产品判据：学生不必为了收通知带手机；教师一条内容只录一次；普通通知上课不占屏；关闭网站或断网不惩罚学生。五秒发布是目标，当前没有真人计时证据。

## B · 竞品已经解决什么

依据官网功能描述，不把营销效果声称当成研究结果；未做穷尽市场调查，也不声称「市面没有」。

| 类型 / 官方来源 | 已解决的需求 | 在本校约束下仍需验证的缺口 |
| --- | --- | --- |
| [Forest](https://www.forestapp.cc/) · 番茄钟 | 时间约束、减少切换、成长可视化 | 无手机时是否仍需要计时？退出损失是否增加负担？ |
| [Focusmate](https://www.focusmate.com/) · 虚拟陪伴 | 通过共同工作的约定帮助启动 | 摄像头、网络、预约与未成年人的隐私边界是否适配？ |
| [Todoist](https://www.todoist.com/features) · 任务管理 | 快速捕捉、描述、子任务、提醒与跨端组织 | 记录推理上下文的成本，是否比“未完成”任务更低？已有描述栏也能承担此功能，需实测模板价值 |
| [LifeAt](https://lifeat.io/) · 沉浸空间 | 场景、声音、计时、便笺和协作组合 | 校园弱设备与纸笔学习是否需要这些持续画面？ |

同质化观察：计时、音乐、场景、清单和统计反复出现；这是以上样本的交集，不是全市场结论。HAIZ 的可验证差异假设：用“理解到哪里 / 试过什么 / 卡在哪里 / 下次第一步”将任务上下文压缩到一张卡，再把它带到纸上。与自由便笺做交叉试用，比较恢复时长、错误重试、主观负担；不用累计学习分钟数替代学习效果。

## 交付边界

本轮是独立、离线优先的浏览器演示和 Windows 双击 HTML 便携版本，不是已认证的校内通知系统。没有连接个人手机、学校账号或真实 ClassIsland。静态版跨标签同步限同一浏览器配置、同源；新增的 localhost 服务通过真实 HTTP SSE 在独立浏览器配置间同步授权公共内容，仍只绑定本机。离线演示包须接收端重新审核。正式部署前必须补真实身份认证、服务器端授权、签名内容包、不可篡改审计、撤回同步与设备授权。
