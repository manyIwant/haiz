# HAIZ · 校园世界重构计划：技术架构、性能验证与未来整合方案

> **项目对象**：海南中学府城校区（1923，海口市琼山区大路街 187 号）非商业数字校园重构实验
> **实验分支**：`experiment/world-reconstruction`（严格零覆盖 `main` 与现有任何校园资产）
> **核心目标**：建立一套**空间真实、艺术统一、资产可编辑可持续、生态互相耦合、兼顾高视觉品质与普通移动设备流畅运行**的 HAIZ 统一校园世界底层基础。

### 1.2 现有项目的七大根本性问题

1. **双坐标系分裂与空间接缝**：老版 `assets/walk/campus.json`（缺失原始 KML，相对卫星影像 RMS 误差达 `8.9 m`，砚池与艺术中心重叠 `34 m²`，缺少 `2,763 m²` 体育馆）与新版 `twin/data/frame.json` 共存于运行时，只能通过脆弱的仿射修补（`atelier.js`）强行拼接，导致广场高程错台与漫游穿模。
2. **建模质量与艺术风格极端碎片化**：仅前庭约 6 栋建筑拥有高细度 Atelier 建模，而海中最具辨识度的**图书馆银色天文台穹顶与室外大台阶**、**凤栖堂/衍林堂/凤栖亭/衍林亭孔雀绿琉璃瓦屋顶**、**红瓦围合女生宿舍**、**六片绿红相间标准篮球场**、**拱顶体育馆**以及校园外围真实的**府城街区天际线**均被降格为素色灰盒甚至缺席。
3. **资产体积与渲染负载严重超标（移动端难以承受）**：现有自由探索运行时合计下载约 **`116 MB`**（含 `64.3 MB` 未压缩 Atelier PNG 贴图、`31.7 MB` GLB 与 `11 MB` `architecture.glb`），峰值高达 **`6,470,000` 三角面** 与 **`1,100` Draw Calls**，普通移动设备极易因显存峰值崩溃或帧率骤降。
4. **“背景板校园”而非活体世界**：人物、载具、植物、小动物与天气各自孤立——下雨时地面不湿润、无积水反光，人物不撑伞也不前往柱廊/凉亭避雨；晚自习时段教室窗玻璃不会自动亮灯；风场未与树木摇曳和滑翔热气流耦合。
5. **不可持续的黑盒资产生产流**：旧模型分散为一次性手工导出的静态 `.glb`，缺乏参数化可编辑母版（`.blend`）、缺乏统一材质库，也缺乏自动化体积/面数/溯源门禁检验。
6. **不同实验技术栈互不兼容**：漫游、入画、共游、地图与 World Engine 各自维护独立的渲染循环、碰撞体与场景树，任何校园建筑修订都需要在多处重复施工。
7. **溯源标注不透明与边界模糊**：部分推演建筑与真实测绘或照片标定混在一起，用户与后续协作者难以区分哪些细节有公开影像依据、哪些属于艺术复原。

## 二、全新世界架构：一个空间、一套资产、多重体验

### 2.1 唯一空间母版 `HAIZ-ENU-2026`

由 [`world-reconstruction/pipeline/generate_spec.py`](../pipeline/generate_spec.py) 自动将 `twin/data/campus.json` 与标定地标配置编译为唯一权威数据清单 [`world-reconstruction/data/world_spec.json`](../data/world_spec.json)：

- **坐标系**：右手米制 `HAIZ-ENU-2026`（原点锚定一号教学楼门厅中轴 `19.99847892°N, 110.34254843°E`，校园北向 `319.0°`），由 [`engine/core/coord.js`](../engine/core/coord.js) 提供 `Spec/Blender ↔ Three.js ↔ True ENU ↔ WGS84 ↔ 旧版 lanren/V4` 双向零误差转换。
- **全校完整空间覆盖**：
  - **34 栋校内建筑**划分为 5 个校内流式分区 + **133 栋真实 OSM 府城周边城市街区建筑**构成第 6 天际线分区（`d06_fucheng_context`）。
  - **15 片真实运动与景观场地**（400 米标准田径跑道与足球场、6 片蓝绿/红边标准篮球场、3 片排球场、砚池跌水景观等），经自动化空间检查实现 **0 处砚池建筑重叠**。
  - **11 条连通校园道路**、**8 处精选建筑考察视点**、**6 处校园微气候热气流柱**（供滑翔模式乘风攀升）。

### 2.2 艺术视觉语言：「南国书院 · 晴明建构」

我们未盲目追求低效噪杂的写实贴图堆砌，也未退回失真的玩具低模，而是为拥有百年历史的热带名校提炼出鲜明统一的视觉语言：

- **色彩秩序**：**孔雀绿琉璃瓦**（北门牌坊、南门、凤栖堂、衍林堂、凤栖亭、衍林亭）× **海韵赭红琉璃瓦**（一号教学楼、艺术教育中心、女生宿舍）× **火山深青花岗岩基座** × **南国暖象牙灰泥与珊瑚陶砖** × **图书馆蓝绿弧形玻璃幕墙与银灰天文台穹顶**。
- **建构精度**：所有岭南歇山/攒尖屋顶均以参数化双曲举折与飞檐起翘生成；LOD0 建筑均具真实三维凹进窗洞、窗框竖梃与外挑遮阳通廊；百年榄仁树按实拍骨架 `[x,y,z,r]` 放样出经典的 **S 形卧石低枝** 与四季错落绿/红/金叶冠。
- **统一程序化 PBR 材质库**：由纯 `NumPy + bpy` 合成可无缝平铺的琉璃筒瓦、花岗岩砌块、菱形点缀/错缝广场地砖、灰泥、红褐跑道、柏油路面、砚池朱红「硯池」题刻石碑、北门「學中南海」金色匾额与太湖石底座「虎踞龍盤捷報頻傳」铭文贴图，全部内嵌为 WebP 压缩纹理。

### 2.3 可编辑、可持续的 Blender 5.2 参数化生产管线

全部资产均由纯 Python + Blender 5.2.3 LTS Headless 管线确定性生成（全校重建 + 14 个 Draco/WebP GLB 导出 + 5 张 EEVEE 验收渲染仅需 **~1.8–8 秒**）：

```
world_spec.json
   │
   ├── pipeline/blender/materials.py   ← 统一程序化 PBR 贴图与材质库
   ├── pipeline/blender/arch_kit.py    ← MeshBuilder 严格外法向工具 + 岭南曲面飞檐屋顶 + OSM 参数化建筑生成器
   ├── pipeline/blender/landmarks.py   ← 15 处核心地标独立雕刻生成器（北门/一号楼/太湖石/百年榄仁/砚池/艺术中心/图书馆天文台/凤栖堂/衍林堂/双亭/科技楼/体育场看台/南门）
   ├── pipeline/blender/flora_kit.py   ← 6 种热带乔灌原型 + 5 种校园设施原型 + 避撞 GPU 实例化清单 (instances.json)
   └── pipeline/blender/build_world.py ← 导出可编辑母版 assets/blend/HAIZ_World_Master.blend (3.25 MB) + 14 个分区 Draco+WebP GLB + EEVEE 渲染图
   │
   └── pipeline/validate_world.mjs     ← 11 项自动化门禁检验（glTF 结构、Draco、WebP、包体/面数预算、溯源覆盖率、零虚假 surveyed、零砚池重叠）
```

**未来如何持续扩展与修订**：
- 任何新实拍照片或测绘尺寸到位后，只需更新 `world_spec.json` 对应条目或在 `landmarks.py` 中升级对应建筑生成器，运行一条 `blender --background --factory-startup --python world-reconstruction/pipeline/blender/build_world.py` 即可同步刷新母版 `.blend`、所有 LOD0/LOD1 GLB、验证报告与矢量校园总图；
- 美术同学也可以直接用 Blender 打开 [`assets/blend/HAIZ_World_Master.blend`](../assets/blend/HAIZ_World_Master.blend) 按分区 Collection 手工精雕任意单体建筑并回导单个分区 GLB，无需触碰其余分区。

### 3.3 视觉巡检与真实迭代记录

我们在 Blender EEVEE 渲染与真实 Metal-GPU Chromium 17 个机位截图巡检中，主动发现并修复了以下关键视觉与空间缺陷（完整截图经逐张人工目视验收）：
1. **Blender 未合并面法向反转**：移除 `bmesh.ops.recalc_face_normals()` 并对屋顶、窗洞、穹顶、山石、砚池驳岸实施严格外法向校验，根治背面剔除空洞。
2. **中轴柏油大道与砚池水面高程遮挡**：修正草坪、广场与砚池驳岸的精确分区高程（`z = 0.148 m` 柏油、`0.15 m` 草坪、`0.60 m` 前庭广场、`-0.30 m` 砚池水面），并同步更新 `collision.js` 步行高度场。
3. **教学楼通廊护栏双倍 Z 偏移浮空**：通过高空细面自动扫描与渲染检查定位 `arch_kit.py` 护栏叠加两次 `zf` 导致黑线浮于空中的 bug，一次修复并重导出全校 GLB。
4. **水面波点网格与雨天同心圆伪影**：将 `environment.js` 中规则三角函数涟漪替换为多频域扭曲有机 FBM 水面闪光，并将湿润水洼限定在硬化路面（草坪独立处理）。
5. **移动端 390px 顶栏换行与裁切**：重构 `@media (max-width: 720px)` 为两行紧凑排版（上行品牌与海口时刻、下行六枚等宽功能胶囊），彻底消除窄屏裁切。
6. **夜空星点方格感与晚自习建筑可读性**：将星辰改为随机亚像素针点发光，并提升晚自习月光环境基底与暖金教室灯色温。

## 四、面向未来 HAIZ 生态的统一整合方案

本次交付以**完全独立、零破坏的实验分支**呈现，未来可将整套 HAIZ 生态分三阶段平滑整合到这套统一世界底座之上：

1. **阶段 A — 空间与资产层统一（低风险替代底层数据）**
   - 将 `world-reconstruction/data/world_spec.json` 与 `engine/core/coord.js` 提升为全仓共享核心包；
   - 让现有**六幕主页**、**矢量校园地图**与**空间审计工具**直接消费同一份 `world_spec.json`，彻底废弃 RMS 误差 8.9 m 的旧版 `assets/walk/campus.json`。
2. **阶段 B — 场景底座与多体验宿主化（消除重复维护）**
   - 将 **入画（`ruhua` / `painted-lab`）** 直接作为本世界引擎的扩展艺术画境（新增水墨、版画、胶片等镜头着色器预设，零重复建模）；
   - 将 **共游（PR #84）** 多人在线同步层作为插件挂载至 `WorldRuntime.bus` 与 `LivingCampus`（把远程同学渲染为同套骨骼人物，共享同一份碰撞、天气、单车铜铃与钟声）；
   - 将 **自由探索（`free-movement`）** 与 **World Engine（PR #109）** 的叙事彩蛋、校友记忆点与互动任务迁移为挂载在建筑 `haiz_building_id` 上的数据驱动脚本。
3. **阶段 C — 实景精细化与师生共创**
   - 基于 [`PROVENANCE-AND-SOURCES.md`](./PROVENANCE-AND-SOURCES.md) 列出的缺失公开影像清单，由师生/校友补充合法合规的校园外观照片后，逐栋将 `estimated` 建筑升级为 `photo-derived` 精雕模块，并持续保留 `HAIZ_World_Master.blend` 与自动化验证门禁，形成长期可迭代的百年海中数字校园开源工程。
