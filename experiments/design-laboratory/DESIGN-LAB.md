## 1. 先理解 HAIZ：已经存在的那条规律

研究对象：`README.md`、`DESIGN.md`、`START-HERE.md`，`docs/` 中的艺术方向（2026-11-05）、根脉、作品树冠、地图展开、年轮、实验册第二代、入画、校园活着、自由共游、共感暗房、Pocket 文档与 `app/lib` 数据模型、校园玩具箱构想；在 Chromium 中实际打开了首页（六幕）、登录灯光页、Pocket、账户页、实验册、共感暗房、课间窗台、校园杂志、年轮深链接，桌面 1440×900 与手机 390×844 各一遍。

**HAIZ 最好的作品共享一条规律：同一个对象，在不同状态之间连续地变化，而变化本身就是内容。**

| 作品 | 「同一个对象」 | 「状态变化」 | 变化承担的意义 |
| --- | --- | --- | --- |
| 六幕 | 同一棵 V4 榄仁树、同一台摄影机 | 六个镜头之间的轨迹 | 导航 = 在同一空间里移动，而不是换页 |
| 根脉 | 树干 | 从树根向上，颜色从银盐回到饱和 | 时间方向 = 空间方向 |
| 地图展开 | 同一套校园几何 | 总平面 → 每栋楼从自己的轮廓升起 | 读懂 ↔ 置身 |
| 实验册 | 装置 | 印刷线稿 ↔ 立起的实物 | 翻页前躺平、翻过去再立起 |
| 年轮 | 同一棵树 | 点一格，回到那一天 | 数据的选择 = 世界的状态 |
| 入画 | 画布与世界 | 笔触越过画框，落到世界上 | 操作即作品 |

此外还有三条贯穿全项目的习惯：**以树为原点**（校园坐标的原点就是榄仁树）、**诚实标注来处**（读来的 / 算出来的 / 推演的；示例与真实分开）、**不为了统一而抹平作品的个性**。

**问题在哪里。** 全站的「日常界面」——首页右上角的胶囊按钮（全部入口 / 年轮 / 书页 / 声音）、登录页的玻璃卡片、Pocket 的卡片与底部标签、账户页的白屏等待——仍然是通用网页的语言。沉浸作品里有 HAIZ 的规律，一到按钮、表单、设置就断了。所以这次实验的目标不是给作品换皮，而是**把这条规律推进到每一个普通操作里**，并试三种根本不同的推进方式。

## 2. 三套方案总览

| | 句读 | 折 | 年轮 |
| --- | --- | --- | --- |
| 根本思想 | 界面是一句可以改写的话 | 界面是一张纸，信息藏在折里 | 圆心是来处，外圈是此刻 |
| 结构 | 线性：句子 + 夹注 + 疏 | 面：经折装的一折一折 | 极坐标：同心圆 + 准线 |

| 状态 | 句末标点：？。！…… | 折痕、纸的正反面 | 环闭合 / 裂开、点在第几圈 |

## 3. 方案一「句读」

> 横着读是句子，竖着换是选择。

### 3.1 它最根本的设计思想

语言学把一句话分成两条轴：**组合轴**（词按顺序排成句子）和**聚合轴**（每个位置上可以换成的其他词）。「句读」把这两条轴直接做成界面：

- 屏幕上永远是一句完整、可读的中文。它同时说明了**你在哪里、在做什么、还能做什么**。
- 句子里带**实心着重号**的词可以换：点它，可以替换的词沿着竖直方向在它自己的位置上展开。这就是「选择」。
- 带**空心圈**的词带你去别处（链接）。**下划线**是要你写的空（输入）。
- 句末的**标点就是状态**：`？` 还缺东西（点它会带你去缺的地方）· `。` 可以落定（按下它就是提交）· `！` 出了问题 · `……` 正在进行。
- 内容不装进卡片。短的说明写成句中的**双行夹注**（古籍里双行小字的注），长的内容写成句下、用一条朱线连着的**疏**（图片、地图、表格都属于疏）。

### 3.2 它改变了什么

| 传统 | 句读 |
| --- | --- |
| 导航栏 | 主句「我想 [看看 HAIZ]」的谓语；面包屑就是已经写下的上一句 |
| 按钮是装着文字的容器 | 词本身就是控件；提交是句号 |
| 下拉框、单选、分段控件 | 都是「换词」，一种交互 |
| 表单的错误提示框 | 句末变成 `！`，原因注在出错的词旁 |
| 卡片 | 夹注与疏，内容附着在它所属的词上 |
| 设置页的一排开关 | 一段陈述：「动画 [照常]；字 [标准]；颜色 [跟随系统]。」 |
| 危险操作的确认弹窗 | 句子变成问句：「确定让『一台 Windows 电脑』退出吗？[确定] [算了]」 |
| 全局搜索框 | 「我想 ___」——搜索就是把句子补完 |
| 多任务状态 | 页脚的旁白：「专注数学还剩 18:20；收件 2 条待核。」 |

### 3.3 视觉辨识度

去掉 Logo 和颜色，以下几样仍然一眼可认：大字号宋体的完整句子、字下的着重号、句中的双行夹注、左侧一条细线连着的疏、作为按钮的句号。颜色只有纸、墨、朱三种，层级只靠字号和位置。

### 3.4 用户如何理解和操作

只需要学一条规则：**带点的词可以换**。页边常驻「怎么用」四行说明；鼠标悬停时词有底色；键盘 Tab 走到下一个词、↑↓ 直接换、Enter 落定、`/` 搜索；手机上点词，选择栏在拇指上方展开。语法本身帮助发现功能：首页「我想 [走进] [榄仁树·六幕]」里，换了动词，可以接的宾语跟着变（「翻开」→ 实验册，「显影」→ 共感暗房），这让功能的发现变成「造句」。

### 3.5 不同性质的功能

- **沉浸（首页、地图）**：句子与图是同一件事的两种写法。地图里改「想去 [图书馆]」，图上的路线跟着变；点图上的楼，句子跟着变。
- **高频（Pocket）**：「还有 4 件事没做：「整理数学笔记」今天 22:00、……」——勾掉一件事是「点它 → 做完了」，两下；做完的事移进「已经做完：……」那一句，划掉但可恢复。
- **连续操作（专注）**：「我要专注 [25] 分钟，做 [数学]。」按下句号后句子变成「正在专注数学，还剩 24:31……」，旁白里一直可见。
- **数据与阅读（实验册）**：「摆长 [1.00] 米，拉开 [4]°，数 [30] 次全振动……所以 g ≈ 9.80 m/s²。」数字也是词，竖着拖或按 ↑↓ 改变，整句话立即重算；角度超过 5° 时句末变成 `！`，夹注说明小角度近似失效。（反应式数字参考了 Bret Victor 的 Tangle / Explorable Explanations 的原理。）
- **整周课表**这种放不进句子的东西，写成疏里的表——表也是疏的一种。这是规则的边界，不是例外。

### 3.6 运动语言

运动的方向有意义：**竖着动是「换」**（新词从上或下滑进来，方向取决于你选的是列表中靠前还是靠后的词）；**横着动是「进」**（句子重排时其他词横向让位，新的句子从左往右写出来）。词在变化时保持身份（FLIP）。打开选择栏是从词所在的那一行向上下展开。高频操作 140–260 ms，没有常驻动画；「减少动态效果」时全部即时。

### 3.7 为什么适合 HAIZ

HAIZ 是一所中学的数字校园。中文的书写传统——着重号、夹注、疏、句读——是学生每天在课本里见到的东西，也是校史与根脉所属的传统。它让普通的设置页也带着「读书」的气质，而且这种气质来自结构，不来自装饰。它也是三套里对弱网、旧手机、读屏最友好的：几乎只有文字。

### 3.8 实际局限

- **扫视效率**低于对齐的列表：要找「第三件任务」，需要读句子。高频列表多了以后会变慢。
- **依赖文案能力**：每个新功能都要写出好句子；写不好就会变成生硬的「表单朗读」。
- **国际化**几乎不能机械翻译，语序和标点都要重写。
- 手机上长句换行多；词的触控高度约 33 px，略低于 44 px 的建议值（行距弥补了一部分）。
- 依赖宋体。实验室内置了只含页面用字的思源宋体子集（[`shared/fonts.css`](shared/fonts.css)），用户输入的生僻字回落到系统字体。

### 3.9 标志性组件

| 组件 | 规律 |
| --- | --- |
| 词钮 | 实心着重号 = 可换；空心圈 = 去别处。两个选项的词点一下直接切换，三个以上展开聚合栏 |
| 聚合栏 | 选项沿竖直方向在词的原位展开，当前项始终落在词的位置；滚轮 / 竖拖 / ↑↓ / 点 |
| 补白 | 下划线即输入；自动随内容伸长；`？` 点击时聚焦到缺的那个空 |
| 句读 | 句末标点即状态与提交 |
| 夹注 | 双行小字，自动拆成等长两行；不会独占行首（与前一个字、后一个标点粘连） |
| 疏 | 句下内容区，一条朱线连着；图、地图、表都在这里 |
| 旁白 | 页脚的并行任务状态，用「；」连接 |
| 问句确认 | 危险操作把句子改写成问句，答案就是两个词 |

## 4. 方案二「折」

> 展开就是进入，折起就是收好；打开时立起，合上前先躺平。

### 4.1 根本思想

界面是一张有正反两面的卡纸。**层级就是折的深浅，边界就是折痕。**没有弹窗，也不换页：进入一个内容，是把它所在的那一折展开；不需要了，就折起来，只剩一条写着名字的折痕条。桌面上纸横着展开（像经折装），手机上竖着折。

### 4.2 它改变了什么

| 传统 | 折 |
| --- | --- |
| 侧边栏 / 底部标签栏 | **书口索引**：剪在纸边的台阶，桌面在右缘（竖排文字），手机在底边（拇指边） |
| 页面切换 | 旧纸从远端依次折起，新纸从索引那一侧展开 |
| 卡片 | 纸的一折；相邻的折受光不同（山折与谷折） |
| 复选框 | **折角**：把任务的右上角折过来 = 完成，整条任务随之折起，叠到下面「已折起 n 件」那一叠里 |
| 开关 | **翻牌**：翻到纸的背面（背面是蓝的） |
| 分段选择 | **折扇**：选中的一折摊平，其余斜着退后 |
| 滑块 | **拉条**：从缝里抽出一条刻度纸 |
| 删除 / 退出设备 | **撕线**：必须沿齿孔拖过去才撕得下（或键盘连按两次 Enter） |
| 表单错误 | 出错的那一行**留下一道折痕**，改好之后折痕才平 |
| 主要按钮 | **折舌**：从纸边伸出来的一条，按下去纸就折起送出 |

### 4.3 视觉辨识度

折痕的高光与阴影、纸的正反两种颜色、竖排的书口索引、斜退的折扇、蓝色的背面。即使换掉颜色，只要「纸有两面、边界是折痕」这条规律在，就能认出来。

### 4.4 操作

几乎所有操作都是熟悉的点击，只是**点击之后发生的形变就是操作的意义**（完成 = 折起，不是打勾后再消失）。手势只是加速：拖动撕线、拉条，点击永远可用。键盘：Tab 遍历、Enter/Space 激活、数字键 1–6 直达六个索引。

### 4.5 不同性质的功能

- **课表**：过去的课折得很薄，此刻的课完全展开，后面的课半开——**折的深浅 = 时间的远近**。点任何一条都能摊开。
- **任务**：完成的任务不是消失，而是折起来叠在下面，可以摊开找回。
- **收件**：候选像纸条插在袋子里，只露出标题；抽出来才看到原文和猜测，确认后才变成任务，「塞回去」就是不要。
- **专注**：一张纸随时间对折四次，折到最小就结束——剩余时间写在纸上，形状本身也是进度。
- **地图**：一条「把校园从纸上立起来」的拉条，从 0%（平面图）到 100%（立起的整座校园）——同一张纸、同一套坐标。这是 HAIZ 第四幕「总平面 → 三维」规律在普通界面里的版本。
- **实验册**：左页是步骤，右页的单摆是从纸上立起的纸雕；「让装置躺回纸上」就是实验册翻页前的那个动作。

### 4.6 运动语言

所有运动都是纸能做出来的：绕折痕旋转、沿缝滑动、翻面、撕开下落。速度：普通折叠 280 ms，书口切换 180 ms 折起 + 300 ms 展开（依次错开 40–55 ms，看得出「一折接一折」）。可以打断：CSS 过渡会从当前角度反向。

### 4.7 为什么适合 HAIZ

它直接继承了 HAIZ 已经被验证过的两件作品：实验册（装置从纸上立起）和第四幕（同一套几何从平面升起）。它是三套里最容易被学生理解、最容易落地到现有网站的。

### 4.8 实际局限

- 「纸」作为界面隐喻并不新（Material Design 的起点就是纸）。这里不同的是**折**承担语义，但整体仍然最接近熟悉的界面。
- 桌面横向展开时，视口外的折需要横向滚动才看得到，新用户可能不知道右边还有。
- 折扇里斜退的选项文字被透视压缩，可读性下降（手机上已减小角度）。
- CSS 3D 纸雕（地图约 30 栋楼 × 5 个面）在旧手机上的性能**没有实测**。

### 4.9 标志性组件

书口索引 · 折页 / 折痕条 · 折角 · 翻牌 · 折扇 · 拉条 · 折舌 · 撕线 · 收件袋与纸条 · 自折的专注纸 · 纸雕立起（地图、单摆）· 错误折痕。

## 5. 方案三「年轮」

> 圆心是来处，外圈是此刻；转动是周期，向内是更深。

### 5.1 根本思想

HAIZ 的年轮把 1923 年放在树心，把今天放在树皮下。这一方案把这条规律推广为整个界面的坐标系：

- **径向 = 深度**：越往里越早、越私密、越根本、越接近出处；越往外越新、越公开、越接近此刻。
- **角向 = 周期 / 分类**：一天的时刻、一周的日子、一个分类里的各项。
- **准线是固定的**，转动的是圈：**被转到准线上的，就是被选中的**；桌面上准线一直指向右边那一页（选中项与内容之间有一条真实的连线），手机上指向上方的内容。

每个界面都是同一件仪器：

| 样板 | 圆心 | 圈 | 转动 |
| --- | --- | --- | --- |
| 首页 | 1923 · 榄仁树 | 根脉 → 校园 → 作品 → 今天 | 在一圈里挑一项 |
| 登录 | 「进入」 | 账号、口令各一圈；写对一项，那一圈闭合；出错的圈裂开 | 不转；由外向内完成 |
| Pocket | 本周 | 周一到周五五圈，今天最外；还没到的日子是虚线 | 拨时间；准线就是此刻 |
| 地图 | 榄仁树（校园坐标原点） | 地点按真实方位排在外圈；100/200 米距离环；最外圈是太阳 | 转到准线 = 朝它走（整张图跟着转） |
| 实验册 | 出处 | 步骤 → 过程与数据 → 原理 | 在步骤之间走；↑↓ 向内一圈读得更深 |
| 设置 | 我 | 只在这台设备 → 我的账号 → 公开 | 把一项数据拖到另一圈 = 改变谁能看到它 |

### 5.2 它改变了什么

- **导航**是最外圈的一条导航带，转到准线就是去那里。
- **权限管理**变成几何：「作品叶子」这个点在「我的账号」圈上，就是只有我能看到；把它拖到「公开」圈，就是审核通过后公开。数据住在哪里一目了然。
- **表单**是一组闭合的环：进度、有效性、错误位置都在同一个图形里。
- **时间选择**是拨盘：Pocket 里转动今天那一圈，准线指向的时刻和课程显示在右边；专注时长是从此刻向前画出的一段亮弧。
- **危险操作**要按住，直到画满一圈（约一秒；键盘按住空格同样有效）。

### 5.3 视觉辨识度

同心圆、外缘刻度、一条准线、新叶黄绿色的「此刻」。这是三套里图形最强的一套——去掉所有文字，单看结构也能认出。

### 5.4 操作

键盘：**←→ 转动，↑↓ 向外 / 向内换一圈，Enter 选中**。鼠标：拖动、滚轮、点任何一项（它会转到准线上）。手机：拇指沿弧拖动或点击；**转盘放在拇指所在的那个角，可以在设置里换左手 / 右手**；有「收起转盘」按钮把它缩小。右边（手机上方）那一页永远是普通的、可读屏的文字和按钮，转盘不是唯一入口——每个可转的选择在页面上都有对应的普通按钮（例如 Pocket 的「转到」「回到此刻」，设置的「往外一圈」）。

### 5.5 简单任务与复杂任务

简单任务（勾掉一件事、改字号）在右边那一页一步完成；复杂任务（找到某个时刻、比较一周的课、理解数据的公开范围）才交给转盘——**转盘用来理解关系，那一页用来完成操作**。

### 5.6 运动语言

转动有惯性与吸附（放手后按速度多转一点，再吸到最近的一项）；随时可以抓住正在转的圈。换视图时，新的年轮**从圆心向外依次长出来**（每圈错开 18 ms，共约 360 ms）。登录时环随输入逐渐闭合。没有常驻动画，减少动态效果时全部即时。

### 5.7 为什么适合 HAIZ

它直接继承了年轮（时间的画法）、根脉（从过去走向今天的方向）和以树为原点的校园坐标。它让 HAIZ 的核心意象——一棵树和它的年轮——成为全站的结构，而不是一张背景图。

### 5.8 实际局限

- **需要学习一次「转到准线」**。第一次进入时没有引导动画，只有页边的一行提示。
- **登录的环主要是表达**：输入仍然是右边的普通字段，环本身不提供额外的操作价值。这里诚实地说，它在登录里偏装饰。
- **长文阅读**里转盘只承担「深度」导航，阅读本身仍在右侧普通文字中。
- 圈上的标签多了会拥挤（已改为非当前圈只显示准线附近的标签）。
- 手机上转盘约占屏幕下方三分之一。
- 新功能不一定能找到合理的「圈」。如果硬塞，规律就会被稀释。

### 5.9 标志性组件

转盘 + 准线 · 导航带 · 闭环输入 · 刻口选择（短弧上的刻痕） · 刻度弧滑块 · 画满一圈确认 · 范围圈（数据住在哪一圈）· 刻口按钮（带一道缺口的圆，悬停时转动）。

## 6. 三套方案如何与三维世界、漫游连接（推演，未做原型）

这次没有改动三维引擎，也没有做漫游 HUD 原型；以下是每套语言在漫游中的自然延伸，供后续讨论：

- **句读 → 字幕式 HUD**：漫游时屏幕下方只有一行旁白：「你在 [砚池] 边，往北是 [图书馆]。」词仍然可点：点「图书馆」就设为目的地。地图是疏，不是常驻小地图。适合「无 UI 摄影模式」——只剩一行字。
- **折 → 随身地图就是口袋里的纸**：按 M 或点拇指边的书口，一张折着的纸从屏幕边缘展开为平面图；再「立起」就是第四幕。合上时纸先躺平再折起。
- **年轮 → 拇指边的罗盘**：手机横屏漫游时，转盘缩成拇指边的四分之一罗盘：外圈是地点方位（与本实验地图相同的「以树为原点」规律），转到准线就是朝它走；内圈是天气与时间。它天然不是传统游戏 HUD，而且与年轮共享「拨时间 = 改变世界状态」的规律。

## 7. 批判与修订记录

每一轮都在 Chromium 中实际运行：截图（桌面 1440×900、手机 390×844），并用脚本走通交互流程（换词、搜索、登录失败与成功、勾掉任务、数字键盘调节、深色模式；折起与展开、抽出纸条、登录错误折痕、地图立起与放平、撕线退出设备；转盘键盘转动与换圈、搜索跳转、登录闭环、地图转向、范围变更）。最后一轮所有流程无控制台错误。

### 第一轮发现并修改

| 方案 | 问题 | 处理 |
| --- | --- | --- |
| 句读 | 夹注落在行首时独占一行，读起来像排版错误 | 夹注与前一个字、后一个标点粘连，不再孤立 |
| 句读 | 手机上夹注只有约 9 px，读不清 | 最小 11–12 px |
| 句读 | 主句末尾的「。」是可按的，但按了什么也不发生 | 主句改为普通句号；只有真正能落定的句号才是按钮 |
| 句读 | 测试环境没有宋体，整套语言垮成黑体 | 内置思源宋体子集（页面用字 ≈170 KB/字重，常用字按需加载） |
| 折 | 桌面上纸只占一部分宽度，书口索引却贴在屏幕最右边，和纸分离 | 纸按内容收缩，索引跟着纸边走 |
| 折 | 手机上折扇倾斜 38°，选项字被压扁 | 手机上减为 24° |
| 折 / 年轮 | 隐藏的提示条露出一小截黑块 | 不显示时完全隐藏 |
| 年轮 | 转盘标签超出画布被裁掉 | 画布留出边距 |
| 年轮 | 首页四圈标签全部显示，过于拥挤，看不出哪一圈是当前圈 | 非当前圈只显示准线附近的标签 |
| 年轮 | 默认跟随系统浅色，失去「仪器」的识别 | 默认石墨，浅色作为可选 |
| 年轮 | 搜「1988」先跳到「1959—1988 暂时空着」 | 完全匹配优先 |

### 我对自己的质疑（保留下来，未完全解决）

- **哪些真的是原创？** 句读的「标点即状态与提交」「夹注即容器」「语法一致性带来的功能发现」；折的「错误留下折痕」「折的深浅 = 时间远近」「撕线确认」；年轮的「数据住在哪一圈」「表单是闭合的环」「以树为原点、转向即选择的地图」。
- **哪些是已有思想的变形？** 自然语言表单（如 2013 年 Codrops 的 NL Form）、反应式数字（Tangle）、纸的隐喻（Material）、转盘与饼状菜单（iPod 点按轮、Surface Dial）、按住确认。这些在文档里如实列出。
- **哪些只在截图里好看？** 年轮的登录环；折的地图在 100% 立起时，建筑体块在软件渲染下较平淡；句读首页在大屏上右侧大面积留白，第一眼的冲击力弱于现有六幕首页。
- **哪些地方操作困难？** 句读长列表的扫视；折的桌面横向滚动发现性；年轮小半径圈的拖动精度。

## 8. 比较、判断与建议

详细评分表见实验室首页「按验收标准逐项审查」。我的判断：

**以「年轮」作为全站的空间与导航骨架，以「句读」作为普通信息界面的写法。**

- 年轮最能代表 HAIZ：时间、原点、来处，而且已有两件作品（年轮、校园坐标）证明这条规律在 HAIZ 里成立。它适合首页、地图、Pocket 的时间视图、权限设置。
- 句读最能让「每天点击的每一个按钮」成为 HAIZ 的：设置、登录、任务列表、表单、错误提示。它也最省性能、最适合读屏。
- 两者不冲突：转到准线上的那一项，右边那一页正好可以用句子写。
- 「折」是最稳妥、最容易落地的一套，但离「我们自己尚未想到的设计」最远。它的若干组件——撕线、错误折痕、书口索引、打开时立起——值得单独保留，尤其适合实验册和地图。

这只是建议。三套都完整保留在实验室里，请体验之后再决定方向；在方向确认之前，不建议对全站做任何不可逆的替换。

**如果继续推进，建议的下一步（不在本次范围内）：**

1. 在真实 iPhone 与一部中低端 Android 上实测三套方案（尤其是折的 CSS 3D 与年轮的拖动）。
2. 找 5–8 位同学做任务测试：登录、勾掉一件事、找到图书馆、把字调大、让旧设备退出。
3. 若选择「年轮 + 句读」，先在一个低风险页面（如账户页 `src/account/`，它目前确认登录时是一张白页）做第一次落地。
4. 工程上：三套原型都把「视图状态」放在一个对象里、用 hash 路由，可以无损迁移到现有静态站；不需要框架。
