# NIANLUN · Chronoscope / 时间仪 — 极坐标界面设计研究报告

> **核心命题**：如果数字界面从一开始就不是建立在矩形屏幕和直角坐标系之上，而是建立在周期、方向、距离与旋转之上，人类今天会如何使用计算机？

---

## 1. 从第一代「年轮」到第二代「时间仪」

HAIZ 第一代年轮（[`lanren/rings/`](../../lanren/rings/) 与 [`experiments/design-laboratory/nianlun/`](../design-laboratory/nianlun/index.html)）确立了三条基础公理：

1. **圆心是来处，外圈是此刻**（径向表达时间深度与私密性）。
2. **角向表达周期与分类**（一圈是一年，或一天）。
3. **准线固定，转动产生选择**（被转到准线上的，就是被观察的对象）。

第二代实验 **NIANLUN · Chronoscope / 时间仪** 试图突破「静态同心圆看板」的局限，回答一个更本质的问题：**人类对时间的六种观察尺度（时分、昼夜、周律、月相、年轮、纪元），能否统一在同一套连续、可追踪的几何系统中？**

---

## 2. 核心几何与交互规律

### 2.1 单一准线上的多尺度对齐（Single-Ray Temporal Coordinate）

传统日历将「小时」「星期」「月份」「年份」割裂在不同的页面中。在 Chronoscope 中，**所有嵌套的圆环都绕圆心旋转，使其当前时刻精确对齐到同一条径向准线（Sightline）**。

沿着这一条射线，用户同时读出此刻在所有尺度中的位置：
`纪元 (2026)` → `年轮 (十一月 · 小雪)` → `月相 (25日 · 满月)` → `周律 (周三)` → `昼夜 (21:43 · 夜)` → `时分 (:43)`。

**传统日历告诉我们今天是哪一天；时间仪让我们看见这一天在时间中的位置。**

### 2.2 连续尺度透镜（Continuous Radial Scale Lens, σ ∈ [0, 5]）

系统不再使用「切换页面」，而是通过连续参数 $\sigma$ 控制径向空间分配（见 [`js/polar.js`](js/polar.js) 的 `computeScaleLayout`）：

- 当 $\sigma = 1.0$（昼夜）时，昼夜环占据焦点带（$r \in [205, 350]$），时分环退居外缘游标（$r \in [367, 394]$），周律、月相、年轮依次向圆心收缩为上下文环。
- 当 $\sigma$ 平滑增至 $4.0$（年轮）时，年轮环向外膨胀接管焦点带，而原本的昼夜与月相事件则压缩为年轮上对应日期的径向刻度纹理。
- **同一事件在不同尺度下保持身份连续性**：在昼夜尺度是一段有起止角度的弧；在周律尺度是嵌在星期扇区内的微弧；在月相与年轮尺度是落在具体日期辐条上的色痕。

### 2.3 原创极坐标基础组件

| 组件 | 替代的传统控件 | 极坐标语义 |
| --- | --- | --- |
| **极坐标弧段区间选择器** (`createArcRangeSelector`) | 两个 `<input type="time">` 文本框 | 在 24 小时圆环上直接拖动起止手柄，视觉上即时感知跨度、昼夜跨越与已有日程冲突 |
| **连续尺度透镜** (`ScaleLens`) | 多级标签页 / 面包屑 | 径向连续缩放，保持父子周期的几何包含关系 |
| **双准线对比** (`Dual-Sightline`) | 并排双列日历 | 锁定副准线后旋转主盘，直接以角差观察两个日期的昼长差、月相盈亏与周期相位差 |
| **画满一圈确认** (`bindHoldRing`) | 二次确认弹窗 | 危险操作（删除）需按住直到弧线闭合 360°，中途松开立即归零 |
| **拇指象限仪**（移动端） | 缩小的居中圆盘 | 将圆心移出屏幕右下角（支持左手切换至左下角），在拇指自然弧线区展示 260px+ 大半径四分之一圆弧，准线置于 −45° 防遮挡 |

## 3. 真实天文与历法边界

- **真实公历与闰年**：严格按格里高利历计算 28/29/30/31 天与 365/366 天；跨年、跨月及 2 月 29 日重复日程均通过单元测试校验（[`tests/test-astro.mjs`](tests/test-astro.mjs)）。
- **实时星历计算**（[`js/astro.js`](js/astro.js)）：基于 NOAA 太阳位置公式与 J2000 朔望月历元，实时计算任意城市纬度（含海口 20.0°N、北京、东京、伦敦、纽约、雷克雅未克 64.1°N 极昼夜）的日出、日落、太阳高度/方位、月相盈亏与二十四节气。
- **数据边界**：天文数值为程序实时计算；带「示例」标签的日程与「历史」锚点为内置演示/公开历史数据；用户个人新建与编辑存储在浏览器 `localStorage`，不依赖任何后端或账号。

## 4. 自我批判（诚实回答五个核心问题）

### 4.1 哪些部分真正利用了极坐标的优势？
1. **昼夜与光影**：太阳从晨昏线升起、正午居顶、日落入夜，上半圆为昼、下半圆为夜，比线性 0–24 时表格直观得多。
2. **多尺度嵌套关系**：「今天在周、月、年中的位置」通过同心嵌套与单一准线对齐，一眼即可建立全局时空感。
3. **周期比较与弧段选择**：拖动弧段选择时间区间时，能同时看见「这段时间占全天的比例」以及「是否横跨日落」。

### 4.2 哪些部分如果改回矩形界面反而更加优秀？
1. **长文本阅读与事件列表**：十条日程的标题、备注、搜索结果，在右栏（桌面）或上方（手机）使用垂直列表远比强行弯曲排在圆弧上更易扫视。因此本实验刻意采用 **「极坐标仪器 + 矩形观察甲板（Observation Deck）」的混合架构**，不做形式主义。
2. **精确文字输入与日期直达**：输入标题、备注或直接键入 `2024-04-08` 跳转，键盘与输入框仍是最高效的交互。

### 4.3 它究竟是一种界面体系，还是一个漂亮的圆形日历？
在「信息组织（径向 = 层级/深度，角向 = 周期/相位）」「尺度连续缩放（Scale Lens）」与「准线选择」三点上，它已经具备**通用界面体系**的骨架；但在「复杂多维表格编辑」「海量长列表筛选」上，它必须与传统正交文本区域协作，而不能完全取代矩形。

### 4.4 这套交互语言能否扩展到其他复杂软件？
- **音乐 / 音频制作（DAW）**：天然契合——小节、节拍、Loop 相位、多轨谐波共振（代替线性钢琴卷帘）。
- **空间与地图导航**：以观测者为圆心，方位角为方向、径向距离为到达时间（延续 HAIZ 校园坐标规律）。
- **版本历史与文件系统**：以项目原点为树心，分支与提交按时间径向生长，活跃分支位于最外层。

### 4.5 已知局限
1. **桌面与模拟手机验证**：所有截图与 E2E 测试均在无 GPU 的 Chromium（1440×900 与 390×844）中完成，未在真实 iOS/Android 物理机上测试触摸惯性与高刷流畅度。
2. **极小半径的文字密度**：当 $\sigma$ 缩放至内圈时，父尺度环半径缩小，因此内圈主动隐藏了文字标签，仅保留刻度与事件色痕。
3. **无障碍深度**：已提供键盘方向键旋转/缩放与微调按钮降级，但尚未经过 VoiceOver / TalkBack 读屏实测。

## 5. 目录与运行说明

```
experiments/nianlun-lab/
├── index.html          # 时间仪主界面（桌面双栏 / 手机拇指象限）
├── bench.html          # 独立组件与几何验收台
├── css/nianlun.css     # 暗室观测 / 纸面星盘双主题与响应式样式
├── js/
│   ├── astro.js        # 公历、闰年、太阳星历、月相、二十四节气
│   ├── polar.js        # 极坐标几何、连续尺度布局引擎
│   ├── events.js       # 日程、周期重复、历史锚点与本地持久化
│   ├── components.js   # 弧段区间选择器、画满一圈确认等原创组件
│   └── app.js          # 主控制器、惯性物理、SVG 渲染
├── tests/
│   ├── test-astro.mjs  # Node 历法与天文单元测试（8 项）
│   └── test-e2e.py     # Playwright 桌面+手机端到端测试与截图
├── shots/              # 实机渲染截图
└── RESEARCH.md         # 本研究报告
```

本地运行与测试：
```bash
# 1. 运行天文与几何单元测试
node experiments/nianlun-lab/tests/test-astro.mjs

# 2. 运行 Playwright 桌面+手机 E2E 测试并更新截图
python3 experiments/nianlun-lab/tests/test-e2e.py

# 3. 本地静态预览
python3 -m http.server 8080
# 访问 http://127.0.0.1:8080/experiments/nianlun-lab/index.html
```
