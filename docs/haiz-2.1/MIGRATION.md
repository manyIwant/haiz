# HAIZ 2.1 数据兼容、冲突合并与恢复（取代 2.0 版说明）

> 2.0 的 `docs/haiz-2.0/MIGRATION.md` 有一处**错误**：它写"服务器保留每次写入的完整快照（带版本号）"。实际上 `pocket_snapshots` 每个用户只有一行，每次保存都会**覆盖** `data`；`version` 只用于防止并发覆盖（比较并交换），不是历史。本文件纠正这一点，并说明 2.1 的改动。

## 1. 线格式与"保护性版本号"

| 记录内容 | 写入的 `version` | 1.5.5 客户端的表现 |
|---|---|---|
| 只有 1.5.5 能表达的数据（任务、课表、专注记录、笔记、外观），或额外只有任务时间戳/专注设置 | `1` | 正常读写。若它再次保存，2.x 的时间戳等扩展会丢失——这些只是辅助信息 |
| 含有**备忘**或**最近删除**（1.5.5 会在保存时静默丢弃的用户内容） | `2` | 拒绝打开：访客空间显示"本地记录暂不可用，原始数据已保留"；账号登录显示"登录失败"。**不会覆盖** |

- 纯 1.5.5 记录在 2.1 中读写仍然逐字节一致（有测试）。
- 2.0 预览客户端只认 `version: 1`，遇到 `version: 2` 同样拒绝打开（只读）。2.0 从未发布，影响仅限开发预览。
- 这是取舍：宁可让旧客户端看不到，也不让它悄悄删掉备忘。1.5.5 的提示文字（尤其"登录失败"）并不准确，这无法从新版本修正。

## 2. 冲突合并（取代 2.0 的"按 ID 全部保留"）

2.0 的 `mergeSnapshots()` 把两边记录按 ID 取并集，会让**另一台设备删除的任务重新出现**，也无法区分"两边都改了同一字段"。

2.1 使用三方合并（`lib/core/snapshot_merge.dart`），以**本设备最后一次与云端确认一致的版本**为共同祖先：

| 情况 | 结果 |
|---|---|
| 只有一边新增 / 修改 / 删除 | 采用那一边 |
| 一边删除，另一边没动 | 删除（不再复活） |
| 一边删除，另一边改过 | 保留改过的版本，并在合并说明中列出 |
| 两边改了同一任务的不同字段 | 两边的修改都保留 |
| 两边改了同一字段 | 采用修改时间较晚的一边，列出 |
| 两边都改了任务笔记 | 两段都保留 |
| 两边都改了同一条备忘 | 保留较新的，较早的另存为一条备忘 |
| 专注记录 | 只增不删，取并集 |
| 没有共同祖先（例如本次启动后从未成功读到云端） | 退回并集，并明确告诉用户"无法识别删除" |

合并后会弹出说明，列出应用了哪些对方的修改、哪些项在两边都改过。测试见 `test/snapshot_merge_test.dart`。

限制：共同祖先只保存在内存里。App 在冲突期间被关闭后再打开，会重新读取云端最新版本作为新的起点——冲突前本机未保存的修改不会带到下次启动（这与 2.0 相同：账号数据不落盘到本机）。

## 3. 恢复：实际能做到什么

| 场景 | 能否恢复 | 方式 |
|---|---|---|
| 访客空间，回到升级 2.x 之前的状态 | 能 | 2.x 第一次打开时保存的 `personal.v1.pre2`（只写一次、永不覆盖），由支持人员复制回 `personal.v1`；之后在 2.x 中做的修改会丢失 |
| 访客空间，误删任务 | 能 | 「待办 → 最近删除」，最多 60 条 |
| 访客空间，换设备或清理浏览器数据 | 只有提前导出过才能 | 「我的 → 数据与备份」导出的文件 |
| 账号数据，回到某个旧版本 | **不能** | 服务器只保存最新一份；没有历史版本 |
| 账号数据，误删任务 | 能（本设备） | 「最近删除」会随记录一起同步保存 |
| 账号数据，冲突时选了"使用云端版本" | 不能 | 本机未保存的修改被放弃；对话框会先说明这一点 |

服务器端历史的建议方案见 [proposals/pocket_snapshot_history.sql](proposals/pocket_snapshot_history.sql)。它**没有部署，也没有在真实 Supabase 上验证**。部署前需要评审 RLS、存储量与保留期限。
