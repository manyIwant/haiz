# 账号与数据管理发布验证 · 2026-11-04

用户明确要求发布 main，并保证用户注册登录、管理自己的数据。网站后端现默认开启普通注册，所有应用 HTML 由服务端验证会话，正式灯光登录保留原入口。新账号固定学生权限，教师/管理员由已有管理员授权。

后续按用户提醒保留原灯光正式登录界面：`/login/` 沿用原视觉，接真实注册、登录、邀请与二次会话验证；移除账号中心另造的登录表单，所有未认证页面返回灯光入口。原 `/api/auth/*` 与新 API 使用同一服务端会话，未验证不能触发成功点灯。

账号中心实现便签/收藏/偏好读取、创建、编辑、版本冲突保护、删除、分页和本机 JSON 导出；密码修改、设备会话撤销、全部退出，以及验证密码/账号名后的账号注销。服务端使用当前会话的 owner，不接受请求体伪造 owner 来访问别人记录。最后管理员不能注销。

重点验证：共享 Cookie 在另一标签从 A 切成 B 时，旧 A 页面读、写和导出均被身份前置条件拒绝。独立审查曾复现混合导出，修复后真实 HTTP 复测为 `blocked:true, downloadCreated:false`。旧工作台也注入相同保护，浏览器本地存储按已验证账号分隔，清理 A 不删除 B；旧访客数据不自动归属账号。

真实浏览器使用本机虚构验收账号登录、创建便签、刷新后读回，账号中心布局及交互正常；验收数据不写入提交。main 目录布局单独测试，确认根站点正常加载、页面需要登录、私有目录与内部软链接均不能读取。未来数据库版本拒绝启动，现有 v1 可事务升级至 v2。

发布为基于远程最新树的增量提交：只新增 backend/、src/account/、CI 与说明，并合并原 package.json 脚本/.gitignore，不覆盖 main 已有校园模型、Flutter Pocket、Supabase、Academic 或发行包。
