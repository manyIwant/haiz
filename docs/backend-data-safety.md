# 个人数据恢复、查询与自动备份

这批能力沿用原有账号与会话，仅供网站 Node 后端使用。每个接口仍校验本人身份；管理员通过这些个人接口也只能看到管理员自己的内容。正式入口仍是既有深蓝暖光 `/login/`，登录后的 `/account/` 增加搜索、回收站、历史版本、操作记录和用量。

## 数据恢复

个人便签、收藏、偏好每次成功修改前保存旧版本。回收站中的内容可恢复，历史面板可以查看旧版并恢复为一个新版本。恢复不会减小版本号；旧设备以旧版本写入会收到409，不能覆盖恢复结果。

保留范围为：归档后30天，每条最多20个旧版本，每个账号最多2000个旧版本，先到上限者生效。长时间没有改过的内容被删除时才归档，因此不会因为原创建时间很早而立即丢失。超过范围的旧正文会被清理，删除标记继续保留以防旧设备覆盖。回收站只显示仍有可恢复正文的内容，因此删除标记数可能大于回收站条目数。

历史保存在私有数据库中，不会返回给其他账号，也不进入公开教师通知。注销账号清除数据库中的历史版本；服务器备份中的副本按备份策略轮换，不能把注销描述为所有历史副本瞬时消失。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/data/:collection/:id/history` | 当前版本及保留中的旧版本，最新在前；返回 `items,retention` |
| POST | `/api/v1/data/:collection/:id/restore` | `{expectedRevision,revision?}`；省略revision仅恢复已删除记录的最新可用正文 |
| GET | `/api/v1/trash/:collection` | `limit=1..200&cursor=记录ID`；返回 `items,nextCursor`，revision为当前删除标记版本 |

`collection` 是 notes、bookmarks、preferences。恢复必须带当前版本；指定的历史版本必须属于本人、同一集合、同一ID且含未删除正文。找不到或已到期返回404；恢复冲突返回409及remote。

## 搜索、用量与本人操作记录

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/search` | `q=关键词&collection=可选集合&limit=1..200&cursor=集合:ID`；返回 `items,nextCursor`，每项带collection |
| GET | `/api/v1/usage` | 三集合的有效条数、删除标记、JSON字节数和历史版本用量，以及当前限制 |
| GET | `/api/v1/activity` | `limit=1..200&cursor=数字`；本人操作，按操作序号倒序，返回 `events,nextCursor` |

搜索针对当前未删除记录的JSON文本，关键词1至100字符，按字面子串匹配；百分号、下划线不是通配符。默认搜索全部三集合，按集合和ID分页。当前上限5000条，暂不接外部搜索服务；这是有界扫描，不宣称全文索引。

用量中的 bytes/historyBytes 为UTF-8 JSON内容字节数，不是SQLite文件或磁盘配额。最多5000条个人记录，包括删除标记；每条最多16000字节。历史额外受数量与时间限制。

操作记录仅包含动作、对象ID、版本和时间，不含正文、密码、会话令牌、IP地址或其他账号事件。全库审计保留最近约10000条，因此它是近期活动记录，不是永久账本。

## 自动备份

生产服务默认启动自动备份：首次没有可用备份时创建，随后每天备份，最多保留最新7个完成的备份。开发默认关闭；可用 `HAIZ_BACKUP_INTERVAL_HOURS=1..168` 设置间隔，设0关闭。服务正常退出时等待进行中的备份收尾，再关闭数据库。

备份位于私有数据目录的 `backups/` 中，目录0700、文件0600。使用SQLite在线backup，写临时文件后由独立Worker执行quick_check，通过后原子发布并轮换；失败不会删除之前的可用备份。最新旧备份损坏时记录失败并从正常主库重新生成，不会一直卡住后续备份。备份工作不在HTTP主线程执行。原有 `backend:backup` 手动备份命令仍可用。

systemd示例允许最多300秒停机收尾，覆盖HTTP排空与最多120秒的完整性检查。若极慢磁盘使备份超过停机时限，systemd会强制结束，未发布的临时文件不能用于恢复；此前完成的备份仍可用。实际大库部署应根据恢复演练测得的时间调整该上限。

管理员 `/api/v1/admin/metrics` 增加 `backup` 状态，包含是否启用、是否运行、最后成功/失败时间和保留数量，不返回备份路径或凭据。

这是本机自动备份。它能处理部分误操作、当前数据库损坏等恢复场景，无法抵御整块磁盘丢失；正式运维仍需把备份复制到受控异地存储，并定期恢复演练。恢复仍采用原有流程：停服，将已完成备份放入新的私有目录命名为haiz.sqlite，再启动验证，不能复制旧wal/shm文件。

## 上线范围

已实现的网站API不自动修改 Flutter Pocket/Supabase 或 Academic 独立服务。GitHub main 的代码发布也不会在GitHub Pages上启动Node进程；公网登录和备份需要真实Node+Caddy部署后生效。
