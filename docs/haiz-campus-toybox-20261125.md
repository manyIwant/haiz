# HAIZ · 校园玩具箱（Campus Toybox）
 
- 日期：2026-11-25
- 状态：用户认可的长期产品构想；尚未实施
- 起源：游戏化真人验证 V1 的六款原创玩偶；V1 预览位于 `preview/human-verification/`
- 优先级：先验收验证 V2 的艺术表现，再独立规划收藏馆；不把收藏系统作为登录上线的前置条件。

## 核心构想

让真人验证中的原创玩偶走出验证码，成为 HAIZ 校园世界里具有连续性、辨识度和故事的角色。学生可以在个人空间中的校园玩具箱/收藏馆欣赏角色，查看它们的校园故事和不同外观。角色也可在入画（RuHua）、共游（Stroll）及校园漫游场景里出现。它们不应仅仅是 UI 图标，而是可在不同空间中复用的三维角色资产。

## 艺术与资产原则

- 圆润可爱、柔软有触感、有鲜明轮廓和各自的性格；克制配色、温暖光影、真实材质与卡通造型结合。
- 优先保持原型角色辨识度而非机械复刻。榄仁小芽是否成为 HAIZ 吉祥物留待后续决定。
- 统一角色 ID、版本、名称、配色、尺度、原点、材质、模型及动画接口；渲染场景与资产解耦。
- 允许程序化模型或可独立导出的 GLB/glTF，保留原始可编辑源码、贴图和许可信息。未来漫游可按性能选择不同 LOD。
- 可探索眨眼、呼吸、轻摆、走动等自然小动作，以及校园活动、季节与故事主题的外观。
- 角色登记表应稳定；不同应用通过同一角色 ID 引用资产，不在各模块各自重新造型。

## 收藏馆设想（待设计）

- 个人空间中可旋转、放大、观察玩偶的展示架；可以有角色故事与校园地点联动。
- 未来在榄仁树下、校园生活场景中自然遇见角色；是否开放装饰、换装或展示互动，由后续设计评估。
- 校园活动可引入主题外观，强调文化与纪念性，不采用付费抽奖、概率奖励、稀缺性压力或连续签到压力。

## 与认证的边界（长期约束）

- 真人验证的目标是防滥用，不是发放收藏奖励。收藏权益与验证次数、成功与失败完全解耦；不鼓励重复触发验证。
- 不能因为收藏状态而改变安全阈值或授予登录权限；正式认证仍由可信服务端与独立反机器人机制决定。
- 不采集学生生物识别数据，不保存不必要的行为轨迹。收藏系统若未来上线，遵循最小数据原则、用户权限控制及可访问性设计。
- V1/V2 独立预览均不得接入真实账号或替换正式登录。

## 后续路线（建议，非已承诺功能）

1. Gemini 完成 V2 角色和抓娃娃机的视觉升级，保留独立资产接口。
2. 艺术验收通过后，由工程侧审核资产、建立共享目录与注册表；避免重复资源。
3. 单独设计收藏馆原型，再评估与个人空间、入画和共游的集成。
4. 正式认证安全工作独立进行：服务端挑战、限流、短时一次性凭证、会话绑定、独立反机器人服务及无障碍替代流程。
