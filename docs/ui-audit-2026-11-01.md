# HAIZ UI audit · 2026-11-01

Scope: `main` source reviewed; changes proposed on `design/8pt-ui-foundations-20261101`. This is a **source-level first pass**, not a completed pixel-by-pixel visual acceptance test.

## Product direction

Keep HAIZ's own campus voice: warm paper, deep ocean/charcoal, copper accents, photography and architecture as the protagonists. Functional screens should be quiet and predictable; cinematic descent, campus 3D and editorial storytelling intentionally retain freer compositions. Do not replace the brand wholesale with a generic AI dashboard.

## Design rules

1. **Spacing:** 8px progression (`8/16/24/32/48/80`); 4px optical alignment is allowed. In Flutter, use `PocketSpace`. Responsive/immersive layouts may use fluid values where the 8px rule would harm composition.
2. **Type:** screen/UI sizes have named roles rather than arbitrary numbers. Flutter baseline: `12` micro, `13` caption, `14` body, `18` section, `32` page title. Chinese uses a native CJK-friendly system font; keep bundled Sora for existing Latin UI. Consider Geist **only after** license, loading, CJK fallback and layout checks.
3. **Colors:** keep Porcelain/Obsidian/Ocean semantics. Copper/teal accent communicates active/important states; avoid enormous decorative gradient areas. Neutral surfaces can be opaque; don't force glass everywhere.
4. **Icons:** one visual family per navigation surface, consistent size/stroke/selected behavior. Do **not** replace every pictogram or brand illustration indiscriminately.
5. **Motion:** communicate state transitions, not novelty; honor reduced motion and keep content immediately usable.
6. **Accessibility:** functional controls target at least 44×44 logical/CSS px where appropriate; visible keyboard focus, readable labels, non-color-only selection, and safe-area behavior. Verify contrast by actual renders; don't infer compliance from palette values alone.
