# 九个问题与可验证的答案

在收到后半段需求后、开始补充 P0 同步层之前，已在对话中逐项回答；此文保存答案和验收方法。最初文本截断，续文已于本轮开发中补齐，后续要求全部纳入本地实验层。

1. **学生完全不带手机仍有价值吗？** 有可验证的价值假设：课堂公共屏承载准备事项与活动入口，线下领取材料，纸笔卡让学习不依赖屏幕。若后排不能看清、通知出现时不合适，价值就不成立；需要授权观察和后排辨读测试。
2. **教师确实更省时吗？** 尚不能证明。五秒发布是目标；现有原型减少内容重复录入，但新增审核与确认也有成本。比较现有流程和 HAIZ 各完成 5 个任务的中位耗时、错误修改时间及重复传达次数。
3. **已有 ClassIsland，HAIZ 有什么必要性？** 本地验证了班级范围、内容审核、课程附加材料与资源复用。HAIZ 不增加排课或铃声引擎。如果学校现有工具已经很好地解决内容流转，则无需再安装 HAIZ；产品必要性不能靠重复成熟能力证明。
4. **自习室超出普通番茄钟吗？** 原型实现了四条推理线索、中断后恢复、独立空间便笺和理解变化书架。它也可以被普通便笺替代；需要比较记录成本和恢复速度，不能据功能存在就断言学习效果提升。
5. **服务器关闭能否上课？** 本地实验服务与 ClassIsland 完全独立，不触碰其进程和程序文件。HAIZ 已缓存页面和未过期公告可只读，过期信息移除；教师随时隐藏和切回授课软件。真实希沃焦点及遮挡行为还须授权真机验证。
6. **不准安装时的替代？** 使用普通个人/测试电脑上的单文件 HTML，或本地 Node 服务和多个浏览器配置。无需在希沃安装；若连网页打开也不被允许，演示仍只在测试电脑上进行。不绕过学校策略。
7. **真正需要与开发者兴趣怎样区分？** 准备事项、漏通知、恢复任务是待验证需求；体素天气、机位收藏、漫游是体验探索。后者保留第一轮，但不作为 P0/P1 成功证据。
8. **砍掉一半，只留三个？** 授权发布到公共屏、思路中断与恢复、离线只读与一键隐藏。四个空间属于可减的呈现层，不能挤占前述可靠性工作。
9. **谁的反馈能证明有效？** 找至少 3 名未参与开发的教师（含班主任与学科教师）完成任务观察；邀请自愿学生用纸笔与网站交替试用两周。预先定义恢复思路耗时、漏带/漏通知、重复录入时间、退出和不用的原因。允许无改善或负结果；不用活跃时长、签到数替代收益。研究必须获得适当授权并避免收集成绩、身份、课堂录音或行为监控数据。

## 本轮架构取舍

ClassIsland → 官方插件/IPC Bridge（报告与适配契约，未实连）→ Classroom（可运行）→ localhost Backend（可运行的角色与班级演示）→ Teacher/Student Web（可运行）。选择以模拟适配器完成闭环；没有目标版本与 Windows 环境，因此不在插件和 IPC 之间伪作已验证的技术选型。

没有摄像分析、录音、学生注意力监测、后台个人行为追踪、教师密码收集、校园内网探测或远程命令执行。性能采样只在自动化测试浏览器进程上运行，不进入产品页面。
