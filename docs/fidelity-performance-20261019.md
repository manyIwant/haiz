# 实拍构件与保真性能改进 · 2026-10-19

**后续调整：** 用户反馈加载等待过长，已恢复原先的按需加载：开场不等待校园，点击开始后加载三维，盆栽靠近后加载。下文关于播放前全量预热和两分钟等待的是此前方案，已撤销；索引合批、静态缓存、阴影合批、精确碰撞及稳定分辨率继续保留。

目标：保留既有纹理分辨率、抗锯齿、阴影、反射、树叶风动和气候效果，允许更长准备时间，不以动态降画质换取流畅。

## 不删细节的优化

- 原合批过程把索引几何展开成独立三角形。现在保留原索引与各顶点的位置、法线、UV、颜色，三角面不删减，恢复显卡顶点缓存利用。
- 世界构建完成后缓存静态局部变换；显式保留风扇、灯光及其目标的动态更新。叶片风动仍由逐帧着色器执行，水、云、雨仍保持原更新逻辑。
- 305 个树脚接触阴影按空间块合并，保留原四边形、纹理、透明度及正常视锥裁剪。
- 行走使用均匀网格筛选候选碰撞体，窄相位仍是原圆形角色／矩形碰撞检测；原步进与滑墙不变。
- 雨丝平面偏移预计算，减少逐帧三角函数；去除水面与石岸热循环中临时向量分配。
- 移除低帧率自动降低像素比例的逻辑。保留用户原有手动画质选项与原自动设备档位，不新增任何距离、雨量、阴影或纹理降级。
- 加载期间上传场景纹理、预编译材质，并提前解码近景盆栽。电影首页先准备三维校园再启用播放按钮，避免播放时同时构建校园；完全不可见的预载校园不执行逐帧模拟，实际过渡到校园时恢复。
- 开场仍保留故障退路：三维准备报错或超过两分钟后允许观看地理影像，并保留独立校园入口。没有无限等待。

## 证据与限制

固定 640×400、像素比例 1、2048 阴影和同一砚池机位的初始探针：静态缓存与阴影合批使每帧矩阵重算从 4,658 降至 92，绘制调用从 691 降至 561。此为增加艺术中心细节前的隔离测量，不等于最终全场景 FPS 提升。

最终报告见 `tests/performance-browser-results.json`。测试在相同最终场景中分别开启／关闭静态缓存，并从实际 WebGL 帧缓冲读取像素对照；同时对索引／展开几何做同样对照。还核对 4,000 个碰撞采样、风扇世界矩阵变化及全部树脚阴影数量。`tests/walk/verify.cjs` 检查多条完整行走轨迹的一致性。

最终探针（已包含艺术中心细节和预加载盆栽）记录每帧 98 次矩阵重算、562 次绘制调用；索引保留减少 1,521,342 个重复顶点。静态缓存对照和索引／展开对照的 1,024,000 个帧缓冲通道值均无差异。4,000 个碰撞采样无差异；此轮批量查询耗时约 41.9 ms → 1.0 ms，仅代表该批查询，不是每帧总耗时。

这里使用 SwiftShader 软件渲染，多进程争用及驱动等待会明显影响耗时。提交耗时、矩阵次数、绘制调用与顶点数量不是实际手机 GPU 帧率；不承诺所有设备零掉帧。新增细节也会增加三角面开销，须结合具体设备做硬件帧时间测试。静态缓存只用于已知不移动的世界物体；未来新增动画对象应标记 `userData.dynamicTransform=true`，或显式恢复其 `matrixAutoUpdate`。
