# HAIZ v1.4 — student migration and dialog regression fixes

Scope: feature branch based on `feat/student-data-isolation-v1.4` (`b65c783`). This does **not** merge Academic into GitHub Pages `main`, which has no common Git ancestor with the Academic preview.

## Bugs reproduced before the fix

- QA-STORAGE-01: concurrent task edits during the legacy ownership claim lost newly added tasks.
- QA-STORAGE-02: an impossible calendar day such as `2026-02-31` was accepted.
- QA-UI-01/02: Study Relay dialog controller disposed while Flutter's exit transition still used it.
- Command palette: the same disposed-controller problem reproduced when selecting or closing search results.

## Changes

- Re-check account identity inside the migration queue; check conflicts before claiming ownership. Rebase legacy records onto current in-memory tasks after asynchronous claim and destination writes; schedule the final merged snapshot after earlier queued writes and wait for persistence.
- Reject normalized-invalid calendar dates, preserving original data.
- Give Study Relay and command search dialogs lifecycle-owned text controllers.
- Add QA concurrency, account-switching, destination-write gating, second-import, date, Study Relay, and search navigation regression tests.

## Validation on connected macOS Apple Silicon environment

- `flutter analyze --no-pub`: **0 issues**.
- `flutter test --no-pub --coverage`: **86 passed, 4 tagged live tests skipped**.
- Line coverage: **1798 / 2232 = 80.56%**, meeting the 80% static gate.
- Deterministic pre-fix tests were confirmed to fail; post-fix tests passed.
- No production accounts, school student records, or real school data used.

## Still blocked for main/release

- GitHub Pages `main` contains no Academic Flutter app tree and has **no common ancestor** with the Academic preview baseline. This fix must be integrated into that lineage, with explicit product decisions before any main merge.
- Need combined PR21/PR22/PR24 integration tests and newly triggered hosted CI; local feature-branch tests do not certify the combined release.
- Need Android device / iOS WebView / Windows ClassIsland / authorized school and QQ environment verification, plus end-to-end delta-sync and recovery behavior before production deployment.
- Other dialog forms using caller-owned controllers should be separately audited (e.g. inbox and schedule), not assumed safe.
