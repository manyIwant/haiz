## 一、结论先行

1. **HAIZ 最破坏沉浸感的不是材质，是“可信度断崖”**：一棵近乎写实的榄仁树，立在一个本不存在的岩岛上，岛上放着一块放错了位置的“虎踞龙盘”，旁边是均匀白墙、蓝窗的体块楼（见 `docs/ruhua/01-hold.jpg`）；每一幕右侧都盖着一张玻璃卡片；七套各自为政的渲染器里有三种“校园北”。观众不需要懂建筑也能感到“这里是布景”。
2. **这些问题大多可以用证据解决，而不是用特效遮住**。本次用卫星影像叠加、三张校园照片的相机反解，核清了树与石头的关系、两株榄仁树、校园方位（第四节）。
3. **样本选了一条路，而不是十个页面**：清晨从北门外沿中轴线走到太湖石，再转身走到百年榄仁树下。一镜到底的导演镜头，任何操作都能接过镜头自己走，「导演镜头」从你所在的位置续上。路上三张真实照片会在拍摄者的位置“显影”回原处。
4. **它是一个可检验的作品**：21 项浏览器检查（见第七节）、照片对位残差、卫星对照图、性能计数都随仓库提交。

## 三、诊断：四个问题

### 1. 最破坏沉浸感的是什么

| 问题 | 证据 |
| --- | --- |
| **保真度断崖**：写实的树 + 白模般的楼 + 不存在的岩岛 | `docs/ruhua/01-hold.jpg`；首页 06 截图（树在岛上，背后是均匀蓝窗的白楼） |
| **空间不可信**：岛与太湖石放在树下、校园北有三种取值 | 第四节 |
| **界面盖住场景**：每一幕右侧一张半透明玻璃卡片，占画面约三分之一 | 首页六幕截图（本次在 SwiftShader 中重拍） |
| **世界割裂**：首页 V4（`lanren/js`）、地图（`lanren/map`）、首页漫游（`lanren/world`）、漫步 V1/V2（`lanren/toon`、`lanren/stroll`）、入画（`lanren/ruhua` + `lanren/ruhua-stroll`，与 `stroll` 是同一套文件的拷贝）、`campus-3d.html`（r128，另一套校园）、`descent.html`（另一套坐标）——同一座校园至少七种表达；首页为构图把校园绕树转了 90°，入画只好再把树转 −90° 才能对上 | 仓库目录与 `lanren/ruhua/v4.js`、`lanren/world/compose.js` 注释 |

### 2. 值得保留的独创性

V4 榄仁树本身（逐叶生长、风、透光）；“同一个世界的不同观看状态”的总体思想（第四幕水面显影就是好例子）；年轮对真实数据的诚实画法；入画的“同一几何、两套材质”；以及整个项目**把不确定写在画面上**的习惯——这是 HAIZ 区别于“校园宣传 3D”的地方，应当成为它的视觉身份的一部分，而不是脚注。

### 3. 应删除、简化或重做

- 每一幕的大玻璃卡片：改为与镜头语言一致的字幕和小而实的纸条（本样本示范）。
- 校园语境中的 V4 岩岛与“虎踞龙盘”底座：岩岛只属于第一幕“物种概念”的语境；在校园里应换成树池（本样本示范）。
- `lanren/stroll` 与 `lanren/ruhua-stroll` 的重复拷贝、`sun.js` 中错误的 337°：应合并、修正（未在本次动手，避免影响线上页面）。

### 4. 怎样让场景成为内容

让地点本身携带记录。一条路之所以值得走下去，是因为前面某个位置有人站过、拍下过什么；一株树值得看，是因为能把它与一张真实照片叠在一起，看见模型哪里像、哪里不像。**照片在哪里拍的，就只能在哪里被完整地看到**——这比任何说明文字都更直接地告诉人：这是一个真实的地方。

## 五、三个方案

| 方案 | 做什么 | 艺术价值 | 成本 / 风险 |
| --- | --- | --- | --- |
| **A · 记得的路（选定）** | 一条有真实方位的路线 + 一镜到底的导演镜头 + 照片在拍摄者位置显影回原处 | 让“现实、记忆、模型”成为同一个空间里的三种观看；可信度本身成为美学 | 中。依赖照片相机反解的质量；照片授权待核（沿用现有页面的标注方式） |

## 六、做了什么

### 世界（`world.js`）

- **一个渲染器、一个坐标系**：`buildGeo(campus, null, { rotation: 0 })`，+X 校园东、−Z 校园北（北门），树根在原点。没有为了构图转动任何东西。
- **建筑**：Blender V3（`architecture.glb`）及其原材料；对墙面、石材、混凝土、瓦面加了世界空间的风化（墙脚溅污、楼层线下的雨痕、大尺度色调起伏）；玻璃提高反射。
- **百年榄仁树**：V4 的树皮与叶片原样使用，**去掉岩岛与底座**，换成一个毛石挡墙、花岗岩压顶的抬高树池，北侧四级台阶（区大伟照片里树下有台阶），树池内是 V4 的地被；树整体旋转 180°，让长枝向东伸向那块褐色立石（照片的构成）。树仍是物种概念模型，这一点写在照片纸条里。
- **太湖石**：在数据位置的广场上，0.85 m 黑色花岗岩底座、草皮、一块约 4.6 × 2 m 的多孔灰石（片元级“穿孔”：噪声超过阈值处丢弃，背面压暗，近似水蚀孔洞）。比例按照片反解。
- **地面**：数据里的道路、园林、水体光栅化一次（0.15–0.3 m/像素），铺装的 0.6 × 0.3 m 错缝砖由着色器按真实尺寸画出，远处溶成色调；园林外圈有铺装小径与花岗岩路缘。
- **其他树**：数据里路线 70 m 内的乔木，用与百年树同一种叶片（合成叶簇），分成 40 m 块以便视锥与阴影剔除。棕榈没有画（这种叶片画不了棕榈），保留为天空。
- **光**：太阳由 `sun.js` 的星历在校园坐标中按 **321.6°** 计算。电影设定在 **2026-06-06 07:15**（海口），因为第四节的方位意味着：**11 月的整个上午，一号楼前广场都在楼的阴影里**——楼正面朝向真方位约 322°。「海口此刻」按钮切到真实此刻的太阳，可以亲眼看到这一点。

### 记忆投影（`memory.js`、`memory-shader.js`）

- 三个站点：北门牌楼（学校官网图）、太湖石（项目用户实拍）、百年榄仁树（区大伟 摄）。每张照片的相机位置、方向、视场由照片与模型对位反解（方法与残差写在纸条“照片与模型的差异”里）。
- 所有材质（建筑、树皮、叶、地面、石、天空）共享一组投影 uniform：照片的视图投影矩阵、从拍摄者眼睛渲染的深度图（只在站点切换时渲染一次）、显影前沿、残留量。
  - **对准时**（眼睛距拍摄者 < 约 1.3 m、方向 < 约 9°）：照片从中心逐颗粒显影，约 4 秒到达四角——此时画面就是照片本身。
  - **走开时**：照片留在它照到的表面上，先褪色；视线与拍摄者视线越不一致越淡，掠射角处衰减，离开约 20 m 后消失。向旁边走一步，就能看见真树的光落在概念树上的样子，以及两者哪里对不上。
- 世界里只有两种标记：拍摄者站过的地面圆环（缺口朝向镜头方向）和取景框的四个角，接近时才出现。

### 导演镜头（`film.js`）与自由行走（`walk.js`）

- 分镜写在 `film.js` 顶部，每个运动都写了理由。90.5 秒，一镜到底：街上斜看牌楼 → 横移到官网照片的机位并停留显影 → 穿门洞沿中轴滑行（约 3.5 m/s 的稳定巡航，平滑加减速）→ 太湖石照片机位停留 → 原地转身向东（整片唯一一次转头，朝着晨光和树叶声）→ 走到区大伟的机位停留 → 走进长枝下仰望树冠 → 交出控制权。
- 任何键盘、拖动、触摸都会接过镜头：位置、朝向不变，眼高在一秒内缓到 1.55 m。「回到导演镜头」从路线上最近的点继续，用 1.4 s 混合过去，不跳切。底部时间线上的三个站点可以直接点到。
- 行走有重量（加速约 3 m/s²、停得更快）、步频随速度变化、头部随落脚起伏（2 cm 量级，不晃屏）；建筑、树池挡墙、石头、树干都是实体；树池只能从北侧台阶上去。
- 手机：左半屏拇指出现摇杆、推到边缘是快走；右半屏拖动环顾；所有控件在安全区内；没有键盘依赖。

### 界面与声音

- 没有玻璃卡片。地名字幕像片头字幕一样出现在左下；照片的记录是一张不透明的纸条：标题、来源、拍摄者与年代（没有就写“未注明”）、权利状态、展开可见“照片与模型的差异”与对位方法。
- 声音全部合成，默认关闭：城市底噪（校门外更响）、树叶声（在树冠下更响，随阵风起伏，声像朝向树）、偶尔的鸟鸣（不是物种录音）、脚步（铺装与树池土面不同）。

## 八、已知问题

- 一号楼模型的正门一带在照片里是深色花岗岩、门楣有题字，模型是白墙；楼面材质在北向阴影里仍然偏平。没有为样本重建建筑。
- 北门匾额文字方向与实物相反；石狮缺失（V3 模型问题，已记录，未修改模型）。
- 树池形状、高度与台阶位置是依照片的推测，不是测绘；那块褐色立石的位置依照片构成估计。
- 照片在“走开后残留”时，投到形状差异很大的物体上（例如概念树的树冠）会出现拉伸——这是有意保留的“对不上”，但在叶片上的观感仍偏杂乱，可以进一步只保留在结构面（墙、地、树干）上。
- 合成叶簇的远处行道树形态单一；棕榈未画。
- 电影中的深度图在切换站点那一帧额外渲染一次整场景（约等于一帧的成本）。
- 本样本只覆盖北门—太湖石—榄仁树；**砚池段没有做**。
