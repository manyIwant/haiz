## 1. 出发点

日常校园待办的核心不是「管理时间」，而是用户想到一件事时，能在两秒内记下；做完时轻点右侧勾选，任务自然收起且可恢复。希望得到 Things 3 的克制感、Clear 的任务完成反馈、Superlist 的无摩擦记录，但不复制品牌视觉、代码或交互素材。

目前已在 `main` 实现：首页输入 `quick-memo-input`、`PocketStore.addTask(..., '速记')`、右侧 `task-check-<id>`、划线/淡出、Snackbar 撤销、`TaskView` 四种筛选、个人数据的 account generation 隔离。当前任务状态由 `TaskItem.completed` 表示，日期为可选 `dueIso`，`PocketStore` 同步写入 `PersonalSnapshot`（本地/登录态各自的现有存储）。`TodayPage` 还包含一幅较高的校园图片，列表收拢不是连续过渡。

## 2. 方案比较

| 方案 | 范围 | 取舍 |
| --- | --- | --- |
| A 轻触优化 | 仅改善任务行和动画、保证完成稳定 | 最快上线，但首页仍冗长，也不支持便捷日期 |
| **B 日常速记（推荐）** | A + 首页信息层级重排 + 非侵入式日期建议 + 动画/状态解耦 | 工作量适中，沿用现有 Flutter、Store、认证及持久化体系 |
| C 全功能校园任务中心 | B + Android 桌面小组件、推送、跨端同步冲突策略、后台任务 | 价值大但需要原生权限、后台一致性、安全和多端测试；不应和首轮 UI 优化绑在一起 |

**建议默认采用 B**；这是设计提议，不代表用户已明确选定。C 可作为后续独立项目。

## 3. 本轮目标与边界

### 用户目标
1. 从 HAIZ 首页打开后，快速输入并提交一条速记，通常仅需一次输入、一次提交。
2. 完成任务时右侧勾选即时反馈，行内划线/淡出、后续行平滑上移；完成状态可靠保存，不依赖延迟计时器才能提交。
3. 看见简单明确的日期建议，但不被迫填写日期、科目或复杂表单。
4. 可撤销误勾，重新进入「已完成」恢复；账号切换绝不带走其他人的草稿与待办。

### 明确不做
- 不把 HAIZ 变成复杂的日历或番茄钟软件；保留现有「专注」入口，但不让它主导首页。
- 不默认发送提醒、向系统日历写入或读取学校私有接口。
- 不新增用户数据后端、数据库表或无必要的外部 AI 服务。
- 不擅自改变官方班级作业、教师通知的权威状态。
- 不在本轮交付 Android 桌面小组件、iOS Widget 或跨端实时多人共享。

## 4. 页面设计

### 首页布局（手机）

1. 标题「今天。」、日期、小型搜索/通知入口。
2. 顶部固定视觉层级的快速输入栏：「想到什么，随手记下来…」+ 发送按钮。表单为空不可提交；提交后输入框清空并显示新任务。
3. 一行低干扰摘要：「还有 N 件事」，不设置连续打卡、分数或强制激励。
4. 紧接待办列表，按既有截止日期排序；无日期任务保留可见。
5. 课程、校园照片和其他功能变为次级内容。不得影响已有课表和通知入口的可达性。

### 单条任务

左侧标题和小字日期/科目；右侧为至少 44×44 逻辑像素的完整勾选命中区，符合现有三主题配色。编辑、任务来源、删除、专注关联保留在操作菜单或详情中，不挤压标题；长标题最多两行并提供完整编辑入口。大字模式和窄屏不溢出。

### 完成反馈

触发后马上更新 `PocketStore` 的完成状态，随后只在界面层保留短暂视觉副本进行 250–360ms 的勾选形变、文字划线、透明度降低和高度收缩。动效完成后视觉副本移除，下面的任务逐步补位，而不是突然跳动。避免先等 `Future.delayed` 才写入 Store：若用户切后台、切页面或进程结束，仍应保留完成记录。系统设置减少动画时应立即切换完成状态，无需等待。显示简短「已完成 · 撤销」通知，撤销只修改当前账号、同一任务 ID 的完成态。

## 5. 日期建议（小范围）

在 `app/lib/domain/` 增加无副作用、可测试的 `QuickTaskDateParser`，输入为原始文字和参考本地日期，输出为原始标题、可选建议日期与命中范围。首轮只支持清晰表达：`今天`、`明天`、`后天`、`周一…周日`、`下周一…下周日`、有效 YYYY-MM-DD。相对日期使用本地自然日计算；对于同周已过去的星期，建议下一个未来星期并在 UI 明示日期。若模糊、冲突、非法或无法安全解析，**按普通文本保存，不暗中改动内容**。

例如「周五交物理作业」→ 输入框下方出现「建议：周五（11 月 X 日）」日期芯片，用户可点掉、修改或接受；正式保存前以用户最终选择为准。原文标题默认完整保留，不擅自删除日期关键词。此功能可与已有 `TaskEditorSheet` 的日期选择器共用显示逻辑。

## 6. 工程边界与数据流

- `TodayPage` 仅协调页面布局，不继续累积完成动画的所有细节。
- 提取 `QuickCaptureBar`（输入与日期建议）、`PocketTaskRow`（可访问的任务行）、`AnimatedTaskList`（列表插入/移除/收拢）等小组件，尽量减少大页面文件的责任。
- `QuickTaskDateParser` 是纯 Dart 规则解析器，不联网。
- `PocketStore` 继续是唯一事实来源，调用已有 `addTask`、`toggleTask`、`updateTask`；保持 `PersonalSnapshot` 的 version 1 兼容，不改变旧任务的 ID、日期、笔记、来源或完成状态。
- `store.generation` 变化时清空组件草稿、取消待处理 UI 动效及撤销上下文；旧作用域的异步结果不得写入新账号。
- 对于存储失败或只读状态，不静默宣称已成功保存；复用 Store 的错误状态显示可恢复的反馈。云端完成状态仍受现有账号权限限制。

## 7. 最小验收标准

- 快速输入单次提交；连续 10 次新增无重复，无空白任务。
- 完成操作立即改变 Store；离开页面、切后台或快速切换筛选后状态仍正确。
- 任务行右侧勾选清晰，划线/淡出后列表平滑收拢；`reduce motion` 立即执行。
- 撤销与「已完成」恢复都可用；切换账号/访客后旧草稿和撤销操作不会进入新作用域。
- 日期解析单测覆盖月末、年末、周日、非法日期和冲突表达；用户删除日期建议不会改变任务标题。
- `flutter analyze`、`flutter test`、Android QA 构建、iOS 无签名编译、Flutter Web 构建及仓库既有认证/数据隔离回归全部通过。
- 390px 手机窄屏、系统放大文字、暗色主题、键盘交互和触屏操作检查通过。

## 8. 建议实施顺序与发布闸门

### PR 1：可靠的完成过渡
抽出任务行与列表过渡逻辑，立即持久化、流畅收拢、减少动画、可靠撤销。测试覆盖退出页面、连续点击、账号切换和大量任务。

### PR 2：速记优先的首页
压缩或移置大图，减少按钮冗余，让输入框与第一条任务在首屏可达。保留已有日程、班级作业和课表入口。

### PR 3：轻量日期建议
纯 Dart 解析器 + UI 日期建议 + 编辑兼容；日期不明确时不改变任务。

每个 PR 需进行代码评审和相应自动测试；只在全部检查通过且不存在冲突/数据损坏风险时合入 `main`。主分支触发的构建与签名发布须另行检查，不将「代码合并」冒充「APK、IPA 已发行」。
