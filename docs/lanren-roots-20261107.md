## 怎么看

```bash
python3 -m http.server 8080
```

打开 `http://localhost:8080/index.html#roots`（第二幕起点）；`#roots/1923`、`#roots/gate-old`、`#roots/1988`、`#roots/2023` 等可直接打开某一站；`index.html?static` 查看无三维的纯文字史料版。

## 美术方向：整棵树就是放映幕，一百年是一卷正在显影的胶片

1. **投影即光。** 每一站的年份或老照片，从该站摄影机所在的位置投射到它面前的一切：树干、枝条、叶片和地面。站在机位上，图像完整、比例正确；镜头一离开，同一幅图像沿着树的真实深度裂开，在下一个年代重新拼合。照片以"显影"的方式自下而上一粒粒出现。这是真正的空间投影（与机位一致的投影映射），不是贴图，也不是悬浮卡片。
2. **颜色就是时间。** 从 V4 第二幕的彩色镜头走向树根时，颜色被抽走：1923—1950 年代是银盐黑白（冷暗部、暖高光、颗粒、光晕、轻微片门抖动）；1953—1988 的老照片年代是偏棕的单色；1988 年后颜色以褪色彩色慢慢回来；2023 接近正常；「今天」的新叶是第二幕第一次出现的完全饱和的颜色，交给第三幕的新叶特写。
3. **每个年代有自己的光。** 1923 晨光；1938—1946 光几乎熄灭，只剩「停办」那一帧光；1959—1988 没有核实史料，镜头从枝上俯视，一个空的光框落在树根旁的地面上；2023 镜头升到枝干之上、进入阳光。
4. **空间结构来自真实的 V4 树。** 树干是最老的木头，枝梢是最新的生长：路线从树根（1923、1924）、树干（1938—1946，画面一侧是那根向水面低垂又抬起的长枝）、分杈（1950—1953）进入通向第三幕新叶的那根长枝——这根长枝是用树皮网格做体素最短路径从分杈一直找到第三幕镜头所看的叶簇（`lanren/roots/path.js` 的 `LIMB`）。现代的几站从枝下仰望（旧照片落在枝干背阴的一面），2023 升出枝干，「从这里出发」在树冠边缘望向远方的水面，「今天」停在新叶前，随后正是 V4 第三幕镜头。
5. **整段历史期间画面加一道很薄的遮幅黑边**（手机竖屏不加），字幕式的「年份 — 标题」一行加一句话，与可信度标签并列。

## 交互

- **正常滚动** 即在树上爬升：第二幕拥有约 11 屏的滚动长度，每一站一屏左右，ScrollTrigger 吸附到各站（只在第二幕内增加吸附点，其他五幕仍是原来的六个镜头）。
- **年代查找器**（桌面右侧，按树干自下而上排列；手机底部横向滑动）：点击任一年代直达；「全部年代」打开不看镜头的逐条阅读；「跳过 · 进入 03」直接去第三幕。
- **阅读层**：点「展开阅读」、在机位上点击投影、或按 Enter。桌面是右侧纸页，手机是底部抽屉。页面锁定不滚动，镜头向投影处轻轻靠近；内含照片原图（不裁切、保留署名/水印与"授权待确认"说明）、正文、可信度、全部出处（外链 + 本站页面）、关联入口（新闻档案 / 校友 / 建筑观察手册 / 校园手图 / 关于本站），以及上一条 / 下一条 / 全部年代。Esc、点背景或「合上」关闭，镜头回到所在站。
- **地址与返回**：停稳在某一站时地址为 `#roots/<id>`；从阅读层进入新闻等页面再返回，会回到离开时的那一站（sessionStorage 30 分钟）。旧地址 `#campus` 仍打开第二幕。
- **第一幕快捷导航**仍能直接去任意幕；从 01 选 02 落在树根的起点，不强制观看历史。
- **减少动态效果**：跳转即到达，无镜头穿行；胶片的片门抖动与闪烁关闭。
- **无 WebGL / 省流量 / `?static`**：第二幕面板显示完整的纯文字史料清单（`index.html` 中由构建脚本生成，含照片、出处与可信度）。
- **原第二幕的三个入口**（第一人称校园、从星球到树荫、探索导演台）保留在第二幕面板「从树下出发」一组中，沿用原来"沉入树荫"的离场转场；设计文档将它们划归第五幕，待第五幕整合时再移动。

## 与 DESIGN.md 的差异与理由

- DESIGN.md 写"沿树干弧度展开空间时间轴"。实际树干只有约 3 米高便分杈，因此路线是"树干 → 分杈 → 通往第三幕新叶的长枝"；这既符合真实树形，也符合植物学（枝梢是最新的生长），并让第二幕的终点正好是第三幕的镜头。
- 空间时间轴没有做成沿树干排列的标牌，而是"每个年代一个机位，图像只在机位上完整"。理由：避免把树干变成展板，同时让镜头运动本身成为翻阅历史的动作。
- 三个旧入口（漫游、下降、导演台）暂留在第二幕面板，第三幕面板中的「档案 · 来处」三项也未删除（与第二幕节点中的入口重复），以免在其他幕整合前丢失功能。

测试中发现并修复的问题：分段滚动映射起初误用整页滚动高度作分母（与 ScrollTrigger 以 `#track` 为准不一致），导致停在 02 起点时被吸附到下一站；GSAP 3.12 的方向吸附在恰好停在吸附点时仍会前进一格，改为"已在点上就停住"；最后两站机位贴近一根细枝（0.13 m），已移开；「星布四海的人」原误标"多源一致"，改为"学校官网原文"。另外，第二幕停靠点的加长样式有时在 ScrollTrigger 首次测量之后才生效（样式表仍在加载时布局读到的是旧高度），导致其后各幕的进度错位（减少动态效果下从第四幕跳到第六幕）；根因是脚本插入样式表（第二幕自己的、第四幕地图的）仍在加载时，Chrome 对布局查询返回旧样式。现在 `#track` 实际尺寸变化时会刷新 ScrollTrigger，刷新前后重新计算分段映射，并让刷新后的进度立即落位；进度离整数不到 10⁻⁵ 时取整，停在任何一幕时摄影机与 V4 原镜头完全一致。同时，"瞬间跳转"（`goTo(i, true)`：减少动态效果、返回页面时的恢复、测试辅助函数）现在真正瞬间到达——原先 scrub 仍会用约 1.15 秒把镜头扫过中间各幕，第二幕变长后这段扫动会穿过整个历史并打断第四幕的水面显影（ScrollTrigger 实例的 `update()` 使用本帧缓存的滚动值，需调用静态 `ScrollTrigger.update()`）。
