# HAIZ 2.0 数据兼容、迁移与回滚

## 结论

- **不迁移旧数据，只做加法。** 个人记录的线格式仍是 `version: 1`，所有 1.5.5 字段原样保留；2.0 新增内容放在一个顶层可选对象 `haiz2`（内部 `schema: 2`）里。
- 纯 1.5.5 记录在 2.0 中读取再保存，**字节完全一致**（有测试 `a pure 1.5.5 payload round-trips byte for byte`）。
- 访客空间首次被 2.0 打开时，额外保存一份只写一次、永不覆盖的回滚副本：`<namespace>/personal.v1.pre2`。
- Supabase 表结构、RLS、版本号 CAS 均未改动；没有新的数据库迁移。

## `haiz2` 里有什么

| 字段 | 含义 | 1.5.5 看到什么 |
|---|---|---|
| `notes` | 备忘（id、正文、创建/修改时间、可选的关联任务） | 看不到 |
| `taskMeta` | 任务的创建/修改/完成时间、来源备忘 | 看不到；任务本身完整 |
| `trash` | 最近删除的任务及其笔记（最多 60 条） | 看不到 |
| `focus` | 正在进行或暂停的专注会话（开始时间、结束时间或剩余秒数） | 看不到 |
| `completedSessions` | 最近 20 个已记录的会话 id（防止重复记录） | 看不到 |
| `themeMode` / `focusMinutes` | 外观（自动/浅/深）与默认专注时长 | 1.5.5 的 `appearance` 字段随显式选择同步 |

解析是严格的：`haiz2` 格式错误或出现更高的 `schema` 时，整份记录保持只读并保留原文，与 1.5.5 对损坏核心记录的处理一致。

## 混用 1.5.5 与 2.0 时会发生什么

| 场景 | 结果 |
|---|---|
| 2.0 读取 1.5.5 写的记录 | 正常；没有备忘等 2.0 数据 |
| 1.5.5 读取 2.0 写的记录 | 正常读取任务、课表、专注记录、笔记；忽略 `haiz2` |
| 1.5.5 在同一空间**再保存一次** | 1.5.5 不认识 `haiz2`，会把它丢掉：**备忘、最近删除、任务时间、进行中的专注会话会丢失**；任务、课表、专注记录、笔记不受影响 |
| 同一云端账号，2.0 设备打开期间 1.5.5 设备保存 | 2.0 下次保存触发版本冲突，提示"合并 / 使用云端版本"。选"合并"会保留 2.0 内存中的备忘等数据并写回 |
| 2.0 导出的备份 | 含 2.0 数据时备份文件为 `version: 2`；1.5.5 会以"不是受支持的 HAIZ 个人备份"拒绝导入，而不是静默丢弃备忘 |

因此在 2.0 正式发布前，**不要在仍运行 1.5.5 的设备上编辑同一账号**；或在发布说明中明确提示。

## 回滚

1. **访客空间回到 1.5.5**：直接安装/部署 1.5.5 即可，它读取同一个 `personal.v1`。2.0 期间新增、修改的任务和课表都在（因为核心字段始终以 1.5.5 格式写入）；备忘等 2.0 数据会在 1.5.5 首次保存时被丢弃。
2. **需要回到升级前的确切状态**：`personal.v1.pre2` 保存着 2.0 第一次打开该空间时的原始字节。可由支持人员把它复制回 `personal.v1`（浏览器 localStorage / Android SharedPreferences 中同名键）。
3. **云端账号**：~~服务器保留每次写入的完整快照~~ **更正（2.1）**：服务器每个账号只保存最新一份快照，`version` 只用于防止并发覆盖，没有历史版本。见 `docs/haiz-2.1/MIGRATION.md`。

## 待真机/真后端验证

- 用两个虚构测试账号在真实 Supabase 项目上验证：2.0 写入 → 1.5.5 读取 → 1.5.5 写入 → 2.0 冲突处理 → 合并结果。（本次只在测试替身上验证了冲突与合并逻辑。）
- Android 升级安装 2.0 后，`personal.v1.pre2` 是否正确生成（单元测试已覆盖，真机未验证）。
