# HAIZ main 账号发布 · 2026-11-04

目标：将本轮后端发布到 manyIwant/haiz 的最新 main，网站应用入口要求注册登录，每个用户可查看、编辑、删除、导出自己的记录，并管理密码与设备会话。

已确认当前远程 main 为 b05be73b1b3f9732df3aa9322397431dd90a9798，根目录为静态主站，另有 Flutter Pocket/Supabase 和 Academic 服务。当前本地为旧原型副本，不覆盖远程已有校园、Flutter 或教务更新。新增根目录 backend/ 与账号页面，合并根 package.json 脚本和 .gitignore，增加独立 CI。

实施：

- [ ] 真实 HTTP 测试：页面登录门禁、注册、全用户个人 CRUD 隔离、会话管理、账号删除保护。
- [ ] 同源账号中心：登录/注册、三类数据管理、导出、冲突提示、修改密码、设备撤销与账号删除。
- [ ] 服务适配主站根布局与现有原型布局；登录页面开放，校园 HTML 必须持有有效会话，页面提供“我的数据”入口。
- [ ] 部署默认开放普通用户注册，服务端固定学生身份，公开注册不能自行成为教师/管理员。
- [ ] 运行回归、构建、真实浏览器检查和独立审查，再按远程最新 main 的树创建增量提交；以 expected SHA 校验更新 main，不覆盖其他人的新提交。

视觉沿用现有暖纸、深绿、校园手记语言。注册表单聚焦创建个人账号，账号中心用便签/收藏/偏好三项清晰导航；所有内容由用户真实创建，加载、空状态、失败与冲突均显式呈现。

用户补充（同日）：之前制作的灯光登录才是正式入口。正式 `/login/` 直接沿用 main 现有深蓝墙面、暖光和玻璃卡片，只替换认证接入、补齐注册与邀请，不用账号中心另造登录页；`/account/` 仅作为已登录用户的数据管理。灯光成功效果必须在服务端密码验证和二次会话确认后触发。

部署边界：发布 main 是代码发布。GitHub Pages 静态站点不能执行 Node 服务端门禁；必须使用本仓库 Node+Caddy 部署才能把新强制登录覆盖到实际网站。现有 Flutter Pocket 使用独立 Supabase 身份，本轮不以网站登录冒充原生 App 已升级，也不覆盖已发布 APK。
