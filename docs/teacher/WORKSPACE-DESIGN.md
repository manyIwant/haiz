# HAIZ Teacher Workspace · Design Architecture

**Version:** v1.4  
**Design Target:** Editorial Precision × Quiet Technology  
**Mission:** A calm workspace for the people who teach.

---

## 1. 核心设计哲学

> **A calm workspace for the people who teach.**

教学是一项需要专注、秩序与审慎的工作。传统的教务系统往往将技术复杂性直接转嫁给教师：UUID、数据库游标、晦涩的网络超时代码与复杂的同步状态，给使用者带来无尽的心理负担。

HAIZ Teacher 工作台确立以下设计公理：

1. **技术复杂性由系统承担，教师只面对确定性的事实。**
   - 教师永远清楚地知道：正在整理什么、学生将看到什么、哪些作业已确认发布、修改是否已生效。
2. **一个正式作业数据源，一套发布生命周期。**
   - 坚决杜绝以往“本地 localStorage 存一套、后端 SQLite 存一套”的系统割裂。
   - 正式作业以 Academic 服务器记录为唯一权威。
3. **彻底分清「本机草稿」与「正式发布」。**
   - 本机草稿（Local Draft）仅保存在当前浏览器，绝不虚假显示为学生已收到。
   - 只有经 Academic 服务器原子事务确认的状态，才会展示“已发布”凭章。

## 2. 视觉规范与设计系统 (Design System)

以成熟出版专业软件（Editorial Tool）为标杆，拒绝廉价的渐变网格、荧光线条与无意义的卡片悬浮动效。

### 2.1 色彩系统 (Color Tokens)

- **象牙白 (Paper / Ivory, `oklch(97.5% 0.008 85)` / `oklch(95.5% 0.012 85)`)**：
  提供温润、耐看的纸质工作底色，长时间注视不易疲劳。
- **深海蓝 (Sea Ink / Deep Sea, `oklch(24% 0.035 240)` / `oklch(38% 0.06 240)`)**：
  主文字与专业组件用色，沉稳、克制、权威。
- **石墨灰**：正文与辅助元信息分层，真实色值以 tokens.css 为准。工作区自动 axe 扫描没有发现对比度问题；不据此声称全站人工 WCAG 认证。
- **铜金 (Copper, `oklch(42% 0.085 62)`)**：
  作为高亮与关键操作的点缀色（仅在“正式发布”确认等极关键交互中使用）。
- **警示与中止 (Stop Red, `oklch(48% 0.16 26)`)**：
  仅用于版本冲突、不可撤销操作与权限拒绝，避免滥用造成视觉恐慌。

### 2.2 排版与字体系统 (Typography)

- **标题、正文与表单**：本机 Manrope 优先，中文采用明确的系统 CJK 回退；不下载远程字体。字号为 12/14/16/18/20/24/30px 级别，无斜体。字体与色彩的真实值以 `web/teacher/css/tokens.css` 为准。
- 长文本提供字符计数与自动断行保护。

### 2.3 交互与微动效 (Micro-interactions)

- 颜色与透明度过渡 300ms，布局动效 500ms，使用 `cubic-bezier(0.22, 1, 0.36, 1)`。
- 全面支持 `prefers-reduced-motion`，在系统开启减弱动画时自动禁用过渡动画与脉冲效果。

## 3. 工作台四大核心区域

```
┌────────────────────────────────────────────────────────────────────────┐
│  h. HAIZ Teacher                              [当前班级: 高一物理] [退出]│
├──────────────┬─────────────────────────────────────────────────────────┤
│ [One Publish]│  [Workspace: 整理一项作业]                                │
│ • 工作台 (2) │  ┌───────────────────────┬────────────────────────────┐ │
│ • 已发布 (4) │  │ 本机草稿列表          │ 作业编辑器 & 发布前检查     │ │
│ • 历  史 (1) │  │  • 必修一习题 (草稿)  │  • 科目: 物理   • 班级: 1班│ │
│              │  │  • 实验报告 (Review)  │  • 截止时间: 2026-11-02    │ │
│ [课堂预览]   │  │                       │  • 学生端实时预览          │ │
│ • 教室大屏 ↗ │  │                       │  [保存草稿] [进入 Review]   │ │
│ • 账号管理   │  └───────────────────────┴────────────────────────────┘ │
└──────────────┴─────────────────────────────────────────────────────────┘
```

### 3.1 Workspace（作业整理与草稿）
- **左栏草稿区**：展示保存在本地的草稿清单，支持快速切换、创建新草稿与丢弃草稿。
- **中间编辑区**：简洁高效的作业录入表单（科目、目标班级、标题、详细说明、截止时间），集成即时字符校验与格式约束。
- **右栏双重视图**：
  1. **发布前检查 (Review Checklist)**：逐项检查班级、科目、标题、截止时间是否完整无误。
  2. **学生内容预览 (Student Preview)**：展示学生将收到的公开字段，不声称像素级复刻 Flutter 页面。

### 3.2 Published（已正式发布）
- 仅展示经 Academic 后端服务器原子事务确认发布的作业（状态为 `published` 或 `revised`）。
- 实时显示服务器版本号（`v1`, `v2`, ...）与发布时间戳。
- 提供“修改内容”、“撤回”与“版本历史”操作入口。

### 3.3 History（版本变化与撤回记录）
- 完整展示作业从创建、审核、发布、多次修订到撤回的不可篡改历史记录。
- 历史时间线（Timeline）精确记录每一版的：
  - 版本号（如 `v1`, `v2`）
  - 操作类型（创建草稿、提交审核、正式发布、修改内容、撤回作业）
  - 操作时间戳
  - 发生变更的字段明细（如变更了截止时间、标题等）

### 3.4 Classroom（教室屏只读展示）
- 供教室大屏（电子黑板、一体机、ClassIsland 插件）或教师预览使用。
- 仅展示当前班级处于 `published` 或 `revised` 状态的正式作业。
- 杜绝学生个人信息、提交记录、学号等隐私暴露，缩小公开屏幕的数据范围，并在字段不符时拒绝展示。

## 4. 离线整理与数据隔离安全架构

1. **命名空间存储隔离**：
   - 教师登录后，草稿与幂等凭据均隔离保存在专属命名空间：  
     `haiz.teacher.v3.drafts/{origin}/{instanceId}/{userId}`
   - 切换不同教师账号、不同部署实例，本地存储按范围隔离。请求前后与标签页重新激活时复核身份；代理使用捕获的同一 Cookie 校验预期账号并转发。异步结果按登录代次隔离。
   - 每次独立编辑保存独立草稿；发布、Review 和撤回使用独立命令草稿，不覆盖尚未提交的编辑。
2. **纯离线模式 (Offline Organizer)**：
   - 未连接服务器或断网时，教师可点击“离线整理本机草稿”进入纯本地空间（`guest-local`）。
   - 界面明确显示“离线整理”状态与温和提示，发布按钮置灰，绝不让教师误以为已发往服务器。
3. **旧版迁移保留原样**：
   - 检测到旧版 `haiz.teacher.v1.drafts` 时提供显式确认导入入口，导入后保留原数据，不自动私自篡改或清空。
