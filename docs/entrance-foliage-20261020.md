# 门厅与植物形态 · 2026-10-20

## 依据与本轮改动

参考项目既有实拍 `assets/images/campus/campus_yishu.jpg`，不把生成纹理、网上相似建筑或虚构位置当作现场测量。

- 艺术中心入口门廊从楼宽的 27% 收至 22%，檐下高度从 6.4 调至 7.3 模型单位，改善此前过宽、低矮的轮廓。这是单张照片引导的比例推演，不是尺寸标定。
- 将入口处的实心墙拆成背墙、两侧墙体、上楣和门槛，形成 2.1 模型单位的内退空间；玻璃门、门框、上亮和拉手位于凹口内，不再贴在外墙上。新增平台两侧细栏杆和屋脊细栏杆。台阶仍是展示结构，未新增楼内空间或攀爬功能。
- 原有羽状棕榈改为抽生、成熟和下垂三层叶冠，叶长随树高变化。正常画质每株 20 枝，既有低画质选项为 12 枝；没有修改画质自动选择、分辨率或阴影分辨率。
- 两侧种植床保留 36 簇羽状地被，新增 48 簇带枝小叶灌木，用两个实例批次绘制。截图检查后舍弃了过于尖锐的大叶莲座式草稿。
- 土壤和落叶色图为 256×256 原创程序纹理，结合既有程序矿物颗粒法线和粗糙度。叶片沿用原创叶脉图。没有校园实物扫描或新增第三方许可声明。
- 灌木额外复用已经加载的 `terminalia-leaves.webp`：这是项目原有的摄影风格生成素材，不是真实校园照片，来源见 [原始说明](design-notes.md#generated-foliage-asset)。每株四簇有弯曲度、不同朝向的叶簇，合计 192 个实例，两个批次；保留小叶枝条几何。深度材质使用同一透明轮廓和微风位移，纹理失败时仍有立体灌木，不追加下载或等待。

原建筑占地、水体位置和路线保持不变；没有为了接近某一张照片的构图搬动砚池。

## 性能边界

叶片原来为每个三角形重复记录顶点，现在每一片内部共享截面顶点，并保留全部可见表面与轮廓。另去除每片尖端四个零面积三角形，不减少叶片数量。新的共享法线也让弯曲叶面更连贯；这是着色改进，并非声称与旧叶面逐像素相同。

同一 Node 场景检查中，全场景顶点记录从上一提交约 222 万降至约 157 万。这个数字是几何属性记录，不是显存总量，也不是每帧 GPU 时间。新增叶冠、灌木仍会增加三角形数量。

保留索引静态合批、静态变换缓存、精确碰撞索引、微风与阴影同步。没有新增每帧 JS 植物循环、反射 pass 或外部资源下载。开场依然在点击后才请求校园，不恢复全量预热和等待校园就绪的门槛。

## 验证

- `npm run build`：刷新脚本缓存版本，默认首页仍与 `descent.html` 相同。
- `npm test`：包括真实门洞射线、两侧墙体保留、三层叶冠、灌木实例、土壤贴图和 UV、非零叶面、34 个原有地点及 16 间教室通行。
- `npm run test:loading`：桌面和触摸模拟中，校园握手不可用也能播放开场，点击前没有校园请求。
- `npm run test:forecourt`：实际 WebGL 晨光、雨后、俯视、390 px 对照截图；检查入口中轴无新增阻挡。
- `npm run test:performance`：固定分辨率比较同一新版场景的索引/展开与缓存/非缓存结果，检查帧缓冲一致、碰撞一致、吊扇仍动画；不把不同几何版本的耗时当作 FPS 提升。
- `npm run test:browser`：全站桌面/手机布局、入口衔接、漫游及交互回归。

结果见对应 `tests/*results.json`，截图位于本地 `tests/artifacts/forecourt-*.png`。浏览器使用软件 WebGL，不代表真机帧率。建筑背面、精确比例、植被物种和水景对应关系仍有待更多照片与测量；当前效果不是实拍级复刻。
